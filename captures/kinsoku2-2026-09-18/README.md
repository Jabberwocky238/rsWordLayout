# kinsoku2 采集，2026-09-18（Mac Word）

判据：`docs/PREREG-2026-09-18-kinsoku2.md`。夹具 sha256 `57e52d52a706…`。
与 `kinsoku` 唯一的差别：段落属性显式写了 `<w:overflowPunct w:val="false"/>`。

判定 **EVALUATED**：**J-a / J-b / J-c / J-d 各 4/4 全部成立。**

| | overflow 开（kinsoku） | overflow 关（本批） |
| --- | --- | --- |
| Word 逐行字形数 | `[38, 25]` | **`[36, 27]`** |
| 第一行末字形 | `。`，起点 523.33pt，**在边界外** | `天`，起点 492.00pt，**在边界内** |
| 第二行首字 | `春` | `地` |
| 与引擎（恒 36）比 | 差 2 个字符 | **相同** |

**结论：Word 确实有行首禁则。** 默认配置下它没机会动，是因为标点溢出边界先动
（`kinsoku` 那批）。关掉溢出，禁则立刻接手，把第 37 个字「地」带到下一行——
**与引擎逐行一致**。

所以引擎的 CJK 断行（含行首禁则）**是对的**，唯一缺的是 `w:overflowPunct` 那条。
