## 0 三项都用差值绕开未解的 A

纵向的 A（V19）还没解出来——固定比例、固定距离、任何线性 `T + k·L` 都已排除。
但清单上这三项**不必等它**：

| | 怎么绕开 |
| --- | --- |
| **V9 段落间距** | 同设置两段的首行基线之差，**有间距减无间距**就是间距本身。A 相减时消掉。 |
| **V12 `w:position`** | 同一行内抬升 run 与普通 run 的 y 之差。**一行之内 A 根本不参与**。 |
| **V8b `atLeast`** | `line` 足够大时 `atLeast` 应与 `exact` 给出**同一条序列**。比的是两种规则的输出。 |

行距一律 `exact`（已确立与字体、字号无关，font-free / size-free），
好让「行高」是已知量。

噪声底刚在 noise-floor 批独立确认为 **0**（603 个读数逐位相同），所以容差照旧取 0。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 2 预测

### P0 — 每条基线仍落在栅格上

分母 = 采集到的全部基线。第**十九**次独立检验。

### P1 — 段落间距：`@after` 加在段与段之间

每组三段，`w:spacing/@after` = 0 / 120 / 240 / 480 twips。
记该组相邻两段首行基线之差为 `Δ(sp)`：

```
Δ(sp) − Δ(0) = sp / 20  pt
```

**判为假的读数**：任何一个不等。分母 = 3 个非零间距 × 每组 2 个相邻对 = **6**。

### P2 — `w:position`：抬升量 = `@val` 半点，正值向上

同一行内，普通 run 的字形 y 减抬升 run 的字形 y：

```
y_normal − y_raised = val / 2  pt          （y 向下增长，所以正 val 给正差）
```

`@val` = 6 / 12 / −6 / −12 半点（含**负值**，即下沉）。

**判为假的读数**：任何一个不等。分母 = **4**。

### P3 — `atLeast`：`line` 大于自然行高时与 `exact` 同解

`line` = 400 / 520 / 640 twips（20 / 26 / 32pt），都远大于 13pt 的自然行高。
同一 `line` 下 `atLeast` 与 `exact` 各排 6 行。

```
两种规则的第 n 条基线格数**完全相同**
```

**判为假的读数**：任何一个 `(line, n)` 不同。分母 = **18**（3 个 `line` × 6 行）。

### P1、P2 的失败**是我预注册时没想周全**

两条都预测了「精确等于」，而**栅格约束使它不可能精确**：

- 所有基线都在 0.24pt 栅格上（V1，六批确立、1900 多条零例外）；
- 于是任何两条基线之差**必然是 0.24 的整数倍**；
- 而 `sp/20` 与 `val/2` 未必是。

P2 把这一点摆得最清楚：

| `w:position` | 换算 | 是整格吗 | 结果 |
| ---: | --- | --- | --- |
| ±12 半点 | ±6pt = **±25 格** | 是 | **通过** |
| ±6 半点 | ±3pt = **±12.5 格** | **否** | 偏 ±0.12（半格） |

**`val = ±12` 两条全中，`val = ±6` 两条全错，分界正好在「是不是整格」上。**

P1 同理：偏离**恒为 ±0.24（正好一格）**，方向交替。

所以这两条的正确形式应当带上量化。**但判定照记为不成立**——
预注册写死的是精确相等，读数不满足它。要把带量化的形式变成结论，
得有它自己的预注册和夹具。

### P3：`atLeast` 的**行距**与 `exact` 一样，**首行**差 0.72pt

18 处全错，但错得极规整：

```
atLeast  364  447  531  614  697  781
exact    367  450  534  617  700  784
差         −3   −3   −3   −3   −3   −3
```

**逐行差恒为 3 格（0.72pt），不累积。** 两者的相邻行距完全一致
（83 / 84 / 83 / 83 / 84 格），只有起点差 3 格。

所以 `atLeast` 在 `line` 大于自然行高时，**行距确实等于 `line`**（这部分与 `exact` 同），
**但首行位置不同**——首行比 `exact` 高 0.72pt。判据要求逐格相同，所以判假。

### 探索性（§7.5 标「回测」，**不当独立检验**）

三条合起来指向同一件事：**纵向的每一个量都先落到栅格上**，
段落间距、抬升量、首行位置概莫能外。这与 V18（位置是某连续量的截断）一路，
也再次说明 V19 之所以难，是因为「落到栅格」这一步把各种输入量都碾过一遍。

**到此为止，不再往下凑。**

### 对引擎的意义

引擎不改。三条都只排除，没给出可落地的规则；而 P3 揭出的
「`atLeast` 首行与 `exact` 差 0.72pt」是**新的未决项**，不是可以直接写进去的东西。
