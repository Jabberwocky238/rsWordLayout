## 0 为什么只剩这一条路

exact-spacing 与 rounding 两批合起来，把闭式那条路走完了：

| | 结果 |
| --- | --- |
| `y(n) = quantize(y(0) + n × step)` | **判假**（300/342，且与字体无关） |
| 四种进位规则（进位 / 取偶 / 截断 / 向上） | **全部判假**（最高 182/244） |
| 「取最近格」本身 | **判假**——进位与取偶只在平局处不同，差值正是平局步 |

所以问题不在「取整往哪边」，而在**闭式**这个形状。剩下的另一种机制是**递推**：

```
闭式： y(n)   = quantize(y(0) + n × step)      ← 已判假
递推： y(n+1) = quantize(y(n) + step)          ← 本批判它
```

差别在误差往哪走：闭式每次从**起点**重算，递推每次从**已经落位的那一格**继续。
后者是排版实现里很自然的写法——游标落下去，下一行就从落下去的地方起算。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。
位置一律用**有理数**算（格数为 48 分之几），全程不沾浮点——
rounding 那一批的自测教过：浮点误差的量级恰好能把格点推到邻格。

## 2 预测

### S1 — 点预测：**递推 + 半数进位**

以每组**实测的第一条基线** `y(0)` 为锚，全程**用预测值递推**（不是每步拿实测值续）：

```
y(n+1) = quantize(y(n) + step)，quantize = 半数进位
step   = w:line / 20
```

**判为假的读数**：任何一步 ≠ 预测值。分母 = **304**（16 组 × 19 步）。

### S2 — 候选清单（**采集前钉死，不许增删**）

闭式 / 递推 × 四种进位规则 = **8 个**。门槛是 **304 / 304 全中**，不是最高分。
三种结局采集前写死：

- **恰好一个通过** → 在本批范围内它就是那个机制；
- **一个都不通过** → 清单里没有正确答案，机制不在「闭式或递推 × 四种取整」里；
- **不止一个通过** → 本夹具分不开，报出是哪几个，**不许挑一个当结论**。

## 3 夹具为什么这么排（采集前用算术核过）

**递推式下每步的小数部分是恒定的**——每步都从整数格出发，所以小数部分恒等于
`step` 的小数部分。于是平局**只在 `step` 小数恰为 ½ 时出现**。

第一版选的八个 `line` 没有一个是 ½，结果「递推进位」与「递推取偶」
**0 / 152 步分不开**，等于白采。改掉了：现在四个 `line` 的 `step` 小数恰为 ½
（252 / 276 / 348 / 372，即 `L ≡ 12 (mod 24)`），另四个（234 / 266 / 274 / 278）
小数各异。八个候选两两最少 **25 / 152** 步能分开。

字体在这一层不是变量（`exact` 下行距与字体无关，exact-spacing 实测确立：
三族逐组一字不差），所以两个族够用。

| 候选 | 得分 | | 候选 | 得分 |
| --- | ---: | --- | --- | ---: |
| 闭式 · 截断 | **256 / 304** | | 递推 · 取偶 | 30 / 304 |
| 闭式 · 取偶 | 240 / 304 | | 递推 · 截断 | 24 / 304 |
| 闭式 · 进位 | 192 / 304 | | 递推 · 进位 | 22 / 304 |
| 闭式 · 向上 | 134 / 304 | | 递推 · 向上 | 8 / 304 |

### 递推被排除，而且排除得很彻底

递推四种全在 30 / 304 以下，闭式四种全在 134 以上。**两组之间没有重叠。**

残差自己把原因说清楚了。`line = 252` 时每步 52.5 格，递推·进位每步从整格出发
加 52.5 再进位，等于每步走 53 格；实测与预测的差是
−0.24 / −0.24 / −0.48 / −0.48 / −0.72 / −0.72 / −0.96 / −0.96，
**每两步多差一格**。8 步后递推走了 8 × 53 = 424 格，实测走了 420 格 = **52.5 × 8**，
正好是精确值。

所以**位置确实是精确累加出来的**，误差不在每一步上滚——闭式那个形状是对的。

### 但闭式的取整规则仍然不对，而且两批不一致

闭式最高只有 256 / 304。更要紧的是它与上一批**对不上**：

| 规则 | rounding 批 | recursive 批 |
| --- | ---: | ---: |
| 截断 | 168 / 244 | **256 / 304** |
| 取偶 | **182 / 244** | 240 / 304 |
| 进位 | 160 / 244 | 192 / 304 |
| 向上 | 76 / 244 | 134 / 304 |

两批的「最高分」换了规则。**没有哪一种单一取整规则在两批上都占优**，
这本身就说明：位置不是「精确累加 + 某一种固定取整规则」得来的。

### 候选空间到此穷尽

「闭式 / 递推」× 「四种取整规则」= 8 个，**全部判假**。
在「精确累加 + 单一取整」这个框架里，已经没有候选了。

### 探索性（§7.5 标「回测」，**不当独立检验**）

框架之外还剩一个从没考虑过的方向：**有限精度**。
`w:line = 252` twips 是 12.6pt，而 **12.6 在 IEEE 双精度里不能精确表示**；
0.24 同样不能。任何用 `double` 累加并在格边界上比较的实现，都会在
「恰好半格」这类判定上偶尔翻向——而本项目至今的每一个候选都假定算术是精确的。

这能同时解释两件事：为什么没有单一取整规则说得通，
以及为什么两批的「最高分规则」会换人。

**到此为止，不再往下凑。** 要成为判据，得有它自己的预注册和自己的夹具。
