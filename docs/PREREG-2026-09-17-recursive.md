## 0 为什么只剩这一条路

exact-spacing 与 rounding 两批合起来，把闭式那条路走完了：

| | 结果 |
| --- | --- |
| `y(n) = quantize(y(0) + n × step)` | **判假**（300/342，且与字体无关） |
| 四种进位规则（进位 / 取偶 / 截断 / 向上） | **全部判假**（最高 182/244） |
| 「取最近格」本身 | **判假**——进位与取偶只在平局处不同，差值正是平局步 |

所以问题不在「取整往哪边」，而在**闭式**这个形状。剩下的另一种机制是**递推**：

```
闭式： y(n)   = quantize(y(0) + n × step)      ← 已判假
递推： y(n+1) = quantize(y(n) + step)          ← 本批判它
```

差别在误差往哪走：闭式每次从**起点**重算，递推每次从**已经落位的那一格**继续。
后者是排版实现里很自然的写法——游标落下去，下一行就从落下去的地方起算。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。
位置一律用**有理数**算（格数为 48 分之几），全程不沾浮点——
rounding 那一批的自测教过：浮点误差的量级恰好能把格点推到邻格。

### S1 — 点预测：**递推 + 半数进位**

以每组**实测的第一条基线** `y(0)` 为锚，全程**用预测值递推**（不是每步拿实测值续）：

```
y(n+1) = quantize(y(n) + step)，quantize = 半数进位
step   = w:line / 20
```

**判为假的读数**：任何一步 ≠ 预测值。分母 = **304**（16 组 × 19 步）。

### S2 — 候选清单（**采集前钉死，不许增删**）

闭式 / 递推 × 四种进位规则 = **8 个**。门槛是 **304 / 304 全中**，不是最高分。
三种结局采集前写死：

- **恰好一个通过** → 在本批范围内它就是那个机制；
- **一个都不通过** → 清单里没有正确答案，机制不在「闭式或递推 × 四种取整」里；
- **不止一个通过** → 本夹具分不开，报出是哪几个，**不许挑一个当结论**。

## 3 夹具为什么这么排（采集前用算术核过）

**递推式下每步的小数部分是恒定的**——每步都从整数格出发，所以小数部分恒等于
`step` 的小数部分。于是平局**只在 `step` 小数恰为 ½ 时出现**。

第一版选的八个 `line` 没有一个是 ½，结果「递推进位」与「递推取偶」
**0 / 152 步分不开**，等于白采。改掉了：现在四个 `line` 的 `step` 小数恰为 ½
（252 / 276 / 348 / 372，即 `L ≡ 12 (mod 24)`），另四个（234 / 266 / 274 / 278）
小数各异。八个候选两两最少 **25 / 152** 步能分开。

字体在这一层不是变量（`exact` 下行距与字体无关，exact-spacing 实测确立：
三族逐组一字不差），所以两个族够用。
