## 0 为什么要这一份

首行是唯一一项从头到尾没对上过的。试过的形式与它们的成绩（三批合计 60 个首行读数）：

| 形式 | 合计 |
| --- | ---: |
| `72 + quantize(natural) − quantize(descent)`（= T1，**已判假**） | 57 / 60 |
| `quantize(72 + hhea.ascender + lineGap)`（**已判假**） | 45 / 60 |
| `quantize(72 + usWinAscent/upem × 字号)`（**已判假**，12 组分开里 0 中） | — |

而**量化次序已证恒等、穷尽**（见 baseline-order 判据文 §0）。

本批换一个层面：**前五批每一组都用 `w:pageBreakBefore` 起页**，所以那 60 个首行
读数**全部**来自「强制分页之后的第一行」。这一维从头到尾只有一个实例——
正是 §7.2 警告的情形：检验实例与设计实例在被判的那一层上没有区别。

若 Word 对「强制分页起的首行」与「自然溢出起的首行」处理不同，那前五批所有首行
读数都带着同一个混杂因素，而首行恰恰是唯一一直不对的那一项。

**这个怀疑不来自残差**，来自「我自己的夹具在这一维上没有变化」。所以本批线索
**独立于已见读数**——与 baseline-order 那批不同，那批得标注线索不纯净，这批不必。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 2 夹具怎么造出两种首行

每组连排 N 段同设置的短段落，N 取「排满一页再多 3 行」：

- 第 1 段带 `w:pageBreakBefore` → 本组**第 1 页**的首行是**强制分页**起的；
- 内容溢出 → 本组**第 2 页**的首行是**自然溢出**起的。

同组内字体、字号、行距设置**完全相同**，所以两者若不等，只能是起页方式造成的。

## 3 预测

### P0 — 每条基线仍落在栅格上

**判为假**：任何一条基线不是 0.24pt 的整数倍。分母 = 采集到的全部基线。

六个族（Brush Script MT / Khmer Sangam MN / Silom / Lao Sangam MN /
AppleMyungjo / Arial Unicode MS）与前五批无一重合，`upem` 含 **1025**
（AppleMyungjo），`lineGap` 含 **380**（Khmer Sangam MN）。这是第**六**次独立检验。

### P1 — 起页方式不影响首行基线（**本批的点预测**）

```
预测：同一组内，第 2 页的首行基线 − 第 1 页的首行基线 = 0.0000pt
```

**判为假的读数**：任何一组两者不等。分母 = **18**（18 组）。

**这一条不依赖任何公式**，因此也不受「首行到底该用哪个式子」未决的影响。
它只问一件事：起页方式算不算一个变量。

- **成立** → 起页方式不是混杂因素，前五批的首行读数可以合并看，
  问题在别处；
- **判假** → 找到了一个真实的混杂因素，且前五批 60 个首行读数**全部**只覆盖了
  其中一种，那些否定结论的范围要相应收窄。

## 4 对照（**不作预测**）

把 T1（目前最好、已判假的形式）在两类首行上分别算出来报出，好看出
「不对的那些」是不是集中在某一类。分高不改判——T1 已在 first-line 判假。

## 5 采集前声明的排除项

某组**没有跨到第 2 页**（或跨了 3 页以上）时，该组**判不了**，记入分母但不算通过。
夹具已按各字体各字号算过每页能排几行并多留 3 行，正常排版下不该触发。

## 7.1 夹具的修订（**第一次采集之后**）

1. 夹具换掉那两个族（改用 `AppleMyungjo` upem 1025、`Arial Unicode MS`），
   sha256 随之更新；
