**本文在采集之前写死并提交。** 采集后只允许追加「结论」一节（量具方法 §7.1）。

夹具：`fixtures/rounding.docx`，sha256
`bddfa0b24101e017743540d04e22d45a26c2db7c36fbede40264e7651abbfc19`

## 0 为什么只剩这一处

exact-spacing 把自由度逼到了一处。那一批的式子是

```
第 n 条基线 = quantize(b₀ + n × step)
```

- `b₀` 是**实测**的；
- `step = w:line / 20`，`w:line` 是整数 twips，**精确**，不过任何字体度量；
- `n` 是整数。

它 300 / 342 判假，而且**三个字体逐组得分一字不差**（17/17/13/17/17/19），
字体确实不参与。所以**唯一还能错的只有 `quantize` 自己**——要么它的进位规则不对，
要么「位置由这个式子给出」这个前提不对。本批把这两种可能分开判。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 2 夹具怎么把「恰好半格」做成判据

`b₀` 落在栅格上（栅格七批成立，1906 条零例外），所以

```
(b₀ + n × step) / 0.24  的小数部分 = frac(n × line / 4.8)
```

这个小数部分**完全可控**，于是每一步按它分成两类：

| 小数部分 | 意味着 |
| --- | --- |
| **= 0** | 正落在栅格点上，四种进位规则**同解**。**这是前提检验。** |
| **≠ 0** | 规则不同则读数差一格。**这是判据。** |

八个 `line` 值（242 / 246 / 250 / 254 / 258 / 300 / 310 / 324 twips）
除以 4.8 的小数部分覆盖 **.4167 / .25 / .0833 / .9167 / .75 / .5 / .5833 / .5**。

**只取 .5 是不够的**，这一点采集前就核过：半格处「半数进位」与「向上」
永远同解，全是半格的夹具**分不开这两个**。八种小数部分下的两两分离度
（8 个 `line` × 19 步 = 152 步）：

| 两两 | 能分开的步数 |
| --- | ---: |
| 进位 / 取偶 | 15 |
| 进位 / 截断 | 81 |
| 进位 / 向上 | 49 |
| 取偶 / 截断 | 66 |
| 取偶 / 向上 | 64 |
| 截断 / 向上 | 130 |

四种两两都分得开，最少的一对也有 15 步——门槛是全中，一步不同就够判开。

## 3 预测

### R0 — 每条基线仍落在栅格上

分母 = **320**。第**八**次独立检验。

### R1 — 前提检验：偶数步全中

```
预测第 n 条基线（此类步）= b₀ + n × step      （此时它本就落在栅格点上）
```

**判为假的读数**：任何一个「小数部分 = 0」的步 ≠ 预测值。分母 = **60**（采集前算出）。

**R1 判假 ⇒ R2 判不了**，并且结论是「错的不是进位规则，是式子本身」。
这一条**采集前**就写死，免得事后把两种失败混为一谈。

### R2 — 点预测：**半数进位**（round half away from zero）

```
quantize(v) = floor(v / 0.24 + 0.5) × 0.24        （v ≥ 0）
```

**判为假的读数**：任何一个「小数部分 ≠ 0」的步 ≠ 预测值。分母 = **244**（采集前算出）。

## 4 对照（**不作预测**）

同一批奇数步上，另外三种进位规则各自的得分一并报出：

| 记号 | 规则 |
| --- | --- |
| A | 半数**取偶**（banker's rounding） |
| B | **截断**（向下取整，floor） |
| C | **向上**（ceil） |

**分高不改判。** R2 是本批唯一的点预测。四种规则两两能分开的步数见 §2 的表，**采集前已核**：最少的一对 15 步，最多 130 步。

## 4.1 判据脚本在采集前改过一次：**全部换成整数运算**

第一版判据用浮点算「精确位置」，自测立刻露馅：在「游标走 floor」与「走 ceil」
的合成世界里，**R1 也判假了**（50/60、52/60）。R1 本该是四种规则同解的前提检验，
浮点误差的量级恰好能把「正落在格点上」推到邻格，于是 R1 判假就再也推不出
「式子错了」——那正是它存在的理由。

所以精确位置改成**有理数**：`b₀` 落在栅格上，记它是第 g₀ 格，第 k 条的位置就是
`(g₀ × 48 + k × line × 10) / 48` 格，分子分母都是整数；四种进位规则也改成
对有理数取整，一点浮点都不沾。

改完之后四个合成世界的自测（合成侧**独立实现**那四种规则，不与判据共用函数）：

| 合成世界 | R1 | 进位 | 取偶 | 截断 | 向上 |
| --- | --- | ---: | ---: | ---: | ---: |
| 半数进位 | 60/60 | **244/244** | 206 | 84 | 160 |
| 半数取偶 | 60/60 | 206 | **244/244** | 122 | 122 |
| 截断 | 60/60 | 84 | 122 | **244/244** | 0 |
| 向上 | 60/60 | 160 | 122 | 0 | **244/244** |

每个世界里 R1 都成立，且**只有对应那一条**拿到满分。判据能唯一识别四种规则。

这次修改发生在**任何 Word 读数存在之前**。R0 / R1 / R2、候选清单、容差、
证否条件一个字未动，改的只是「怎么算得准」。

## 8 结论

采集包：`captures/rounding-2026-09-17/`。Word for Mac，16 页，1280 字形，
四条证否条件一条都没触发。

| | 判据 | 结果 | |
| --- | --- | ---: | --- |
| **R0** | 每条基线落在栅格上 | **320 / 320** | **成立** |
| **R1** | 前提检验：正落在格点上的步 | **60 / 60** | **成立** |
| **R2** | 进位规则 = 半数进位 | 160 / 244 | **不成立** |

对照（不作预测）：

| 规则 | 得分 |
| --- | ---: |
| 半数进位（点预测） | 160 / 244 |
| 半数取偶 | 182 / 244 |
| 截断 | 168 / 244 |
| 向上 | 76 / 244 |

### 四种进位规则**全部**判假

没有一个接近满分。而且有一条推论比「都不满分」更强：

**半数进位与半数取偶只在平局处不同**，在非平局的步上两者就是同一件事——
「取最近的格」。两者分别 160 与 182，差的 22 正是平局步。
也就是说，**连「取最近格」本身都不对**，不是平局方向选错了。

所以 V14 这一项的四个候选**全灭**。

### 关于 R1，要说句实话

R1 60/60 成立，我在 §3 里把它写成「前提检验：这些步四种规则同解，
它们若也不中，说明式子本身错了」。**它的鉴别力比我当时设想的弱。**

那 60 步的精确位置本来就落在格点上，所以**任何**「大致落到附近那一格」的机制
都会给出同一个答案，不止那四种规则。R1 成立只说明「在格点上 Word 给出那一格」，
**不足以证明式子是对的**。写在这里，免得把它读成比实际更强的证据。

### 探索性（§7.5 标「回测」，**不当独立检验**）

失败的步残差**全部是 −0.24pt**（实测比预测低一格），没有一处 +0.24，也没有两格。
方向一致这件事本身是信息：不像是「取整方向随机选错」，更像是位置由另一条路算出来的。

**到此为止，不再往下凑。**
