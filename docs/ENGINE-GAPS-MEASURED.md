## 量之前修掉的两条（不修就量不动）

这两条是量具在页层直接顶出来的：Word 11 页，引擎 1 页，结构失败，几何读数**根本不产生**。

### G-1 `w:br w:type="page"` 完全没实现

`bridge.rs` 只看 `run.text`，`segments` 里的 `breakKind` 丢掉了。8 个手动分页符全部无效。

**连带一个更隐蔽的错**：rsword 为 `w:br` 在 `run.text` 里放一个 U+FFFC（`￼`）占位符。
整串拿去排版，这个占位符会**被当成一个真字形画出去**——它在 Word 的 PDF 里根本不存在。
于是每个分页符凭空多一个字形，行宽与其后所有字形的原点跟着偏。

已修：`bridge.rs` 改为按 `segments` 拆 run，`engine.rs` 新增 `BreakKind` 与行级 `page_break_after`。

### G-2 分节起始不翻页

`sectPr` 的 `kind` 没被读。已修：`w:sectPr/w:type` 说的是**这一节自己怎么开始**，
`nextPage` / `evenPage` / `oddPage` 起新页，`continuous` 不起。

口径是拿实测对过的，不是照着规范猜的：该夹具 5 个节，`nextPage` 的三节各自起新页、
`continuous` 的两节紧接上一节，**五节的页归属逐条相符**（5/5）。
`nextColumn` 没当成翻页——本版不实现分栏，当成翻页只会凭空多出页来。

**修完的结果**：页 1 → **11**（Word 11 ✓），行 → **20**（Word 20 ✓）。
页与行两层结构完全对上，几何比较这才做得了。

## 量出来的三条缺口

### G-3 段落标记与分页符的字形没有模型 —— 差 14 / 278 个字形

Word 为每个终止符画一个空格字形（§4）。引擎一个都不画。逐条：

| 约定 | 实例数 | Word 画 | 引擎画 |
| --- | ---: | ---: | ---: |
| `PARAGRAPH_MARK` | 11 | 1 个空格 | 0 |
| `PAGE_BREAK_BEFORE_MARK` | 3 | 1 个空格 | 0 |
| `SECTION_BREAK` | 4 | 0 | 0 ✓ |
| `PAGE_BREAK_OWN_LINE` / `MID_PARAGRAPH` | 5 | 0 | 0 ✓ |

11 + 3 = **14**，与实测缺口逐位相等（278 − 264 = 14）。

**未决**：要不要让引擎真的排出这个字形。它是零墨迹的空格，但**占宽度**，
因而影响两端对齐的空隙分配与行尾光标位置。改动会波及 `break_paragraph` 的行宽计算，
本轮**没做**，先记在这里。本文下面的几何数是把这 14 个显式排除出验收范围之后得到的
（§8 的处置；`--exclude-rule`，不是放宽容差）。

### G-4 `SimpleMetrics` 的固定推进量 —— Δx 最大 +12.22pt

`SimpleMetrics` 给西文一律 0.5em。对 Liberation Serif 12pt：

| 字符 | Word 实测 advance | 引擎 | 差 |
| --- | ---: | ---: | ---: |
| 数字 `0`–`9` | 6.0000pt | 6.0000pt | 0.0000 |
| `B` | 8.0040pt | 6.0000pt | **−2.0040** |
| `P` | 6.6720pt | 6.0000pt | −0.6720 |
| `[` `]` | 2.6374pt | 6.0000pt | **+3.3626** |

数字碰巧是 0.5em，**这是巧合，不是桩写对了**——别拿数字行的小差值当作度量没问题的证据。

误差按行累积。264 个配对字形：Δx 中位 +1.35pt，范围 −2.00 ~ **+12.22pt**。

**关键的分解**：每行**第一个**字形的 Δx = **0.0000pt，18 / 18 行全部逐位相同**。
所以横向误差**全部**来自推进量累积，左边距与缩进**一点问题都没有**。
这条把「换真度量」与「查缩进」彻底分开了：后者不用查。

### G-5 基线位置 —— Δy 中位 −1.44pt

每行第一个字形的 Δy：18 行，范围 **−5.52 ~ −1.32pt**，中位 −1.44pt。
引擎把基线放得比 Word 高。

`SimpleMetrics` 取 ascent = 0.8em（12pt 字号即 9.6pt），Word 实测首行基线在内容区顶下
**11.04pt** 处。0.8em 这个经验值就是不对；真值要从字体的 `hhea` / `OS/2` 读。

−5.52pt 那个极值出现在有上标／下标／`w:position` 的行（`B13`–`B15`），
与其余行明显分开——抬升 run 的行高与基线另有规则，**本轮未测**。

## 下一步的顺序（按量具能给出的回报排）

1. **接真度量**（`FontMetrics` 接 skrifa/rustybuzz，读 Liberation Serif 本体）。
   一次同时收掉 G-4 与 G-5 的主体，之后 Δx / Δy 才有资格谈 0。
2. **决定段落标记要不要排**（G-3）。定了才能把那 14 个字形收回验收范围。
3. **抬升 run 的行度量**（G-5 的极值）。需要一份行内混字体／字号的夹具——
   顺带也能补上方法 §8 里「A2 零实例」那条未决项。
4. **现采一次本仓库自己的夹具**。目前所有读数都来自折算的既有采集，
   采集链的前置核查与重复性对照都属于原批次，**没有转移到本仓库**。

## 量具自己在这轮里被改的地方

诚实清单——这些不是引擎的缺口，是量具的：

- **计数模型把分节符当成了段落标记**。整页预期 62、实测 60，闸门拦下，没有串行。
  根因：`\r` 与 `\x0c` 都只占 1 个字符位，只核长度的验证对此不敏感（§7.2）。
  已改为从 `document.xml` 逐字符标注构造，并在 `verify()` 里**声明它核不了终止符身份**。
- **分页符位置只看行内上下文**，把「段中」误判成判不了。已改为同时看段落与行。
- **证否条件 F4 真的触发过**：计数模型说判不了的行，被 §3.2 前置检查的巧合相等
  盖过去判成 OK。已修，留了回归测试。
