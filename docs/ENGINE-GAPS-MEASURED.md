# 引擎缺口：量出来的那些

**这份文件只写量到的东西。** 没量过的写「未测」，不写「应该没问题」。
方法见 [`WORD-LAYOUT-MEASUREMENT-METHOD.md`](WORD-LAYOUT-MEASUREMENT-METHOD.md)，
量具见 [`tools/measure`](../tools/measure/README.md)。

结论日期 2026-09-17。

## 范围（先读这个，别只抄结论）

| | |
| --- | --- |
| 夹具 | **1 份**，`MR1-BREAKS`（11 页、15 段、278 个字形），拉丁文本、Liberation Serif 12pt |
| 采集 | **折算既有采集**（`provenance: ADOPTED`），Word for Mac 16.112.26083020 |
| 平台 | **Mac**。§6.6：Mac 与 Windows 是两套字体度量，**不能互相替代** |
| 归行 | `DERIVED_FROM_LINE_NUMBERS`（Mac 无行盒，**推算不是测量**） |
| 分母 | 20 行全部配上（成立 20 / 不成立 0 / 判不了 0）；264 / 278 个字形进入几何比较 |

**未测**：CJK、表格、脚注、页眉页脚、编号、制表位、跨批次重复性、Windows 侧的任何一条。
本仓库自己的夹具（`fixtures/sample.docx` 等）**一次都没对过 Word**——那需要现采。

## 结果一览

纯文本页（p0–p9，226 个字形）逐步收敛：

| 引擎配置 | Δx max | Δx 中位 | Δy max | Δy 中位 | max\|Δ\| |
| --- | ---: | ---: | ---: | ---: | ---: |
| `SimpleMetrics` 桩 | +12.0144 | +1.3488 | −1.4400 | −1.4400 | **12.0144** |
| 真度量（读字体 + 整形） | −0.4744 | +0.0264 | −0.3400 | −0.3400 | 0.4744 |
| ＋ Mac 纵向栅格 | −0.4592 | −0.0040 | −0.1900 | +0.0100 | 0.4592 |
| ＋ 关字距调整（`w:kern`） | **+0.0244** | −0.0020 | **−0.1900** | +0.0100 | **0.1900** |

单位点。噪声底是 0.0000pt（§5），所以这些**全是信号**，一个都不是「量得不准」。

## 已修（都是量具顶出来的）

### G-1 `w:br w:type="page"` 完全没实现

`bridge.rs` 只看 `run.text`，`segments` 里的 `breakKind` 丢掉了。8 个手动分页符全部无效。

**连带一个更隐蔽的错**：rsword 为 `w:br` 在 `run.text` 里放一个 U+FFFC（`￼`）占位符。
整串拿去排版，这个占位符会**被当成一个真字形画出去**——它在 Word 的 PDF 里根本不存在。

### G-2 分节起始不翻页

`w:sectPr/w:type` 说的是**这一节自己怎么开始**：`nextPage` / `evenPage` / `oddPage` 起新页，
`continuous` 不起。口径拿实测对过——该夹具 5 个节的页归属逐条相符（5/5）。

G-1 + G-2 修完：页 1 → **11**（Word 11 ✓）、行 **20**（Word 20 ✓），页与行两层结构完全对上。

### G-4 `SimpleMetrics` 的固定推进量 → 接真度量

桩给西文一律 0.5 em。对 Liberation Serif 12pt：

| 字符 | Word 实测 | 桩 | 真度量 |
| --- | ---: | ---: | ---: |
| 数字 `0`–`9` | 6.0000pt | 6.0000pt | 6.0000pt |
| `B` | 8.0040pt | 6.0000pt | 8.0039pt |
| `[` `]` | 2.6374pt | 6.0000pt | 2.6367pt |

数字那一行是**巧合**（Liberation Serif 的数字恰好 0.5 em），不是桩写对了。

已实现 `FontEnvMetrics`：`fontenv` 按**码位**选 face，rustybuzz 整形，纵向量取自字体的
`hhea`/`OS/2`。断点仍与桩共用（`linebreak`），所以换度量**不会顺带换断行策略**。

### G-5 基线位置 → 纵向栅格

**实测**：Word for Mac 把基线放在 **1/300 英寸（0.24pt）** 的栅格上。
两份夹具、56 个不同的基线 y，**56/56 全部**是 0.24pt 的整数倍；
同批数据里 x 只有 **1/85** 落在该栅格上——所以这是纵向独有的，不是坐标系的假象。

栅格存在这一条证据强。但下面两条是**拿数据凑出来的**，按 §7.5 标「回测」，**不当独立检验**：

- 行高 = 四舍五入到栅格：只对上 **2** 个点（12pt → 13.68pt，13.92pt → 16.08pt）；
- 基线 = 行高 − 量化后的 descent：只对上 **1** 个点（13.68 − 2.64 = 11.04）。

要证实或推翻，需要一份专门变字号与字体的夹具，本仓库还没有。
实现见 `VerticalGrid`，默认**关**；`layout-trace --vertical-grid mac` 打开。

### G-6 字距调整默认开着，而 Word 没开

`w:kern` 给的是「字号大到多少才启用字距调整」，不写或写 0 就是**不调整**。
rustybuzz 不传 feature 时默认**开**，必须显式关掉。

逼出这条的读数很干净：`B11 section nextPage` 一行，Word 给两个 `1` 各 6.0000pt，
引擎给第一个 `1` 5.5500pt——Liberation Serif 的 `1`+`1` 有一对 kern，rustybuzz 用了，
Word 没用。该行从第二个字形起整体偏 **0.45pt**，而行首字形 Δx 仍是 0.0000。

修完 Δx max 从 0.4592 掉到 **0.0244pt**，正好是半个 twip——**已经触到单位分辨率的底**。

## 仍未解决

### G-3 段落标记与分页符的字形没有模型 —— 14 / 278 个字形

Word 为每个终止符画一个空格字形（§4）：`PARAGRAPH_MARK` 11 个 + `PAGE_BREAK_BEFORE_MARK`
3 个 = **14**，与实测缺口逐位相等（278 − 264 = 14）。引擎一个都不画。

要不要让引擎真排出这个字形是**未决项**：它是零墨迹的空格，但**占宽度**，
因而影响两端对齐的空隙分配与行尾光标位置。本文的几何数都是把这 14 个
**显式排除出验收范围**之后得到的（§8 的处置，`--exclude-rule`，不是放宽容差）。

### G-7 `vertAlign` 与 `w:position` 未实现 —— 目前最大的一项

上标、下标、抬升 run 全都按正文排。抬升 run 页（p10，38 个字形）max|Δ| = **6.8684pt**，
比其余所有页高一个数量级。这不是度量问题，是**功能没做**。

顺带：补上它还能检验方法 §8 里「A2 零实例」那条未决项——那需要一份行内混字体／字号的夹具。

### G-8 `Twips` 的分辨率不够对齐 Word 的纵向栅格

布局单位是 `Twips`（i32，1/1440 英寸 = 0.05pt），Word 的纵向栅格是 1/300 英寸 = 0.24pt
= **4.8 twips**。栅格点根本落不到整 twips 上，两者只在 **1/7200 英寸**上才通约。

后果是一条**下不去的地板**：逐行 Δy 稳定在 +0.01 ~ +0.03pt，就是这么来的。
要真正对上，布局单位得细到 1/7200 英寸——这是架构层面的选择，不是调参。

### G-9 分节边界后的那一行，行高多了正好一格（n=1）

p8 的三行里，`B09 → B10` 的行距是 **13.92pt**，而其余所有同字体同字号的行距都是 **13.68pt**——
差 0.24pt，正好一个栅格单位。B09 带 `sectPr kind=nextPage`，B10 带 `continuous`。

**只有 1 个实例，不下结论。** 现在的处置是记在这里当未决项，不是编一条规则去拟合它
（§7.7：要么留在文本里，要么转成具名未决项，没有第三种）。它是 p0–p9 上
Δy max = 0.19pt 的**唯一**来源；除掉这一行，Δy max 就是 0.03pt。

## 下一步的顺序（按量具能给出的回报排）

1. **`vertAlign` / `w:position`**（G-7）——目前最大的一项，且能顺带补上 A2 的检验实例。
2. **决定段落标记要不要排**（G-3）。定了才能把那 14 个字形收回验收范围。
3. **专门变字号与字体的夹具**——把 G-5 的两条回测规则证实或推翻，顺带查 G-9。
4. **现采一次本仓库自己的夹具**。目前所有读数都来自折算的既有采集，
   采集链的前置核查与重复性对照都属于原批次，**没有转移到本仓库**。
5. 布局单位是否要细到 1/7200 英寸（G-8）——**先别急**，等 1~3 做完再看它还剩多少权重。

## 量具自己在这轮里被改的地方

诚实清单——这些不是引擎的缺口，是量具的：

- **计数模型把分节符当成了段落标记**。整页预期 62、实测 60，闸门拦下，没有串行。
  根因：`\r` 与 `\x0c` 都只占 1 个字符位，只核长度的验证对此不敏感（§7.2）。
  已改为从 `document.xml` 逐字符标注构造，并在 `verify()` 里**声明它核不了终止符身份**。
- **分页符位置只看行内上下文**，把「段中」误判成判不了。已改为同时看段落与行。
- **证否条件 F4 真的触发过**：计数模型说判不了的行，被 §3.2 前置检查的巧合相等
  盖过去判成 OK。已修，留了回归测试。
- **新增 `decompose()`**：按「每行第一个字形」拆差值。它前面没有推进量可累积，
  所以 Δx 只反映行起点、Δy 只反映基线。这条拆法当场排除了「查缩进」整条路——
  首字形 Δx 在桩度量下就已经是 0.0000pt（18/18 行逐位相同）。
