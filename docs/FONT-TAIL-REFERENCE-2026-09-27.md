# 字体高度替代分支的可执行参考

新增 `font_tail.py` 和纯整数模型 `project_alternate_tail`，重放宿主
`100347770 -> 102e4dcac/102e4dec4`。输入是明确的读取点数值；输出停在替代尾返回时，
供后续排版算法实现逐步对照，不自动选择 Word 文档的字体、属性或运行分支。

## 输入和输出

| 参数 | 域与含义 |
| --- | --- |
| `v_prefix_words` | 当前 V 的 `[0,4,8,c,10,14,18]`，恰好七个 i32；不假设仍等于 provider T |
| `tail_p0` | 读取点 P0，u32；本分支消费其中 P.byte1.bit7 |
| `tail_p8` | P8，u16；尺度计算读无符号，最小值计算另按有符号 i16 解释 |
| `tail_p13` | P13，u8；包含 selector、最小值和分量选择位 |
| `metric_byte38` | 可能已被重写的 V38，u8，不从 OS/2 代码页反推 |
| `mode` | 调用者掩码后的 0..3，排除域外诊断调用 |
| `incoming_scale` | wrapper 原 incoming w5，替代尾的 w6；mode 1 消费 |
| `dy` | F174，i32；mode 2 消费，不假定等于 V0 或字体 upem |

所有参数必填。模型按真实 gate 解析 P13，选择 simple tail 时明确拒绝；原有
`font_vertical.py` 的简单尾合同保持不变。P、V 在模型内各读取点之间保持相同，
不模拟并发变化或不透明调用的副作用。

输出保留初始化、重新分配、加量、最小值和最终四个字段 `c0/c4/c8/d0`，以及独立
`stackResult`。后者写入真实调用者的 `SP+1ec`，不是 `F.cc`。模型不填写 `cc`，
也不输出最终 M、LS 行高或 PDF 基线，防止把尚未闭合的下游转换拼成排版结论。

## 已实现的算术

使用已核验的 `native_muldiv`，包含原生舍入、饱和及快路径异常；ADD/SUB 则按
32 位回绕。算术右移保留负奇数向负无穷取整的语义，分量比较按原生有符号 CMP。

- selector 0 把上分量设为 1；selector 1 按算术右移平分；selector 3 根据固定表
  对 V8 而非总和进行比例调整。其它 selector 在非特殊 charset 或 V8>0 时保留
  原分量；仅特殊 charset 且 V8<=0 时使用 105/1000 的重新分配，并保留总和大于
  11 时的额外整数增量。
- `V38 in {128,129,134,136}` 时计算 `extra=N(V0,15,100)`，分别加到 c4 和 c8，
  此路径不再加 V10。其它 charset 的 V10 加入条件仍由 mode、P0 和 P13 计算。
- 最小值初始为 1。P13.bit6 置位时，还比较 `052ffc(3,s16(P8),100)` 和明确
  尺度换算；前者仅在这里的有界参数域中等于 `native_muldiv`，不推广到整个函数。
- 最后根据 charset 和 P13 选择约束 c4 或 `wrap32(c8-c0)`；不回算 c0、d0 或
  stackResult，保留它们来自加量前阶段的值。

源码与完整分支说明见[冻结证据](../artifacts/font-vertical-alternate-tail-2026-09-27/README.md)。
固定表、实际调用参数和字段目的地都有字节或指令依据，不使用拟合倍率。

独立指令检查修正了冻结证据 README 的一条默认分支解释：在 `102e4df5c`，
`CCMP w0,#0,#0,NE` 条件不成立时直接写入 NZCV=0000，随后 `B.GT` 成立。
因此非特殊 charset 会保留原分量，不能按此前文字解释进入 105/1000 分配。
最小反例为 selector=5、charset=0、V4=800、V8=200：正确分量为 800/200，
初版模型却给出 894/106。旧冻结包与初版失败记录保留原字节，本模型和新增反例
按真实指令修正。这也说明自洽的单元测试通过不能替代独立的指令证据核对。

## 运行方式

```sh
python3 tools/measure/font_tail.py \
  --input tools/measure/examples/font-tail-special.json \
  --out artifacts/font-tail-new.json
```

示例完全是合成整数：V0=1000、V4=800、V8=200，charset=134、selector=2，
最小值为 1。结果 c0=800、c4=350、c8=950、d0=0、stackResult=0；V10=75 没有
被加上。只有在基数关系、舍入和最小值均满足特定条件时，总和才等于 1.3 倍，
不能把两次原生整数加量直接替换成浮点倍率。

JSON 输出状态为 `ARITHMETIC_REFERENCE`，保留输入、各阶段值、证据与代码哈希。
重复键、浮点数、bool 冒充整数、未知字段和超域值均拒绝；已有文件、目录及悬空
符号链接都不会覆盖。该命令不调用原生 API，也不启动或附加 Word。

## 接入边界

替代尾之后还存在 `1003482c0` 等字段处理、mode 2 缩放、独立补偿、wrapper 选择
和 LS 聚合。即使选定了本分支，也不能直接把四字段当作最终自然行高。
后续已核对该辅助处理的明确 F 指针传递边，并新增[mode 2 条件连接](FONT-TAIL-MODE2-2026-09-27.md)。
原有仅尾部合同保持不变；新合同仍要求独立 cc 与中间字段稳定条件。
三组 page-start 字体是否实际进入此路径，仍需真实字体请求和运行条件；
当前 Rust 引擎没有启用新的字体倍率。独立字体 API 测量也不替代这项判断。
六字体的新指标和 LOGFONT 观测见[输入实验](PAGE-START-FONT-INPUTS-2026-09-27.md)：
显式 face 转换全部返回 DEFAULT_CHARSET，实际读取点的 charset 仍不能直接取该值。

## 验证

新增模型测试 120 项、CLI 测试 22 项，完整 Python 套件 **965 passed**。
其中包括全部 256 个 charset、全部 65,536 个 P8 值的有符号有界换算，以及
真实分支反例、模式选择、回绕、最小值与输出不变性检查。

独立检查器从已保存的 ARM 指令实现 W 寄存器与 NZCV，不调用模型的运算作为
期望值。修正前它发现上述 CCMP 反例；修正后 **145,925** 组尾部评估通过，
包括全部 P13/V38 组合，另有 **1,000** 组原生乘除边界通过。比对同时检查
最小值裁减前后的分量，避免错误被裁减掩盖。它穷举的是这些指定矩阵，未声称
遍历全部可能的整数输入。

[独立检查包](../artifacts/font-tail-instruction-check-2026-09-27/README.md)保留失败
双方源码、修正后源码和三次执行收据。[参考实现包](../artifacts/font-tail-reference-2026-09-27/README.md)
