# 普通文本到网格输入的条件映射

现有冻结指令已能给出一条有限的输入合同：默认度量回调成功、所列后处理不改变
分量、普通 LS 节点参与聚合且没有其他主导节点时，单个未位移文本节点可归约为：

```text
a = 最终字体指标 M.i32[0]
b = 最终字体指标 M.i32[4]
E = 最终 lslinfo.i32[1c]，即宿主 R64
q = 普通产行调用者的最终 SP274

网格初始 tuple = [wrap32(b + max_signed(a,E)), b, q, 0, 0]
```

这里的单节点归约要求 a/b 非负、回调重算后的 h=wrap32(a+b) 为正且不等于
INT_MAX，并排除 replacement、早期归零、shift 和其他主导贡献。完整的机器字段
前提保存在[条件合同](../artifacts/docgrid-plain-line-components-2026-09-27/README.md)。
“一个可见普通 run”不足以证明这些条件，段落标记等其他节点仍可能参与聚合。

如果 E<=a，H 可进一步缩为 wrap32(a+b)。只有另行证明 q=0，才可将 tuple 写成
`[wrap32(a+b),b,0,0,0]`。这两个条件不能从字体名称、没有上标或缺少观测值推导。

## 两个独立输入

E 来自 LS content-info；只有已证的关闭分支才保证相应输出清零。开启时，上游初值
为零不代表最终 E 仍为零。实际 H 用它与第一字体分量取最大值。

q 则来自 restriction builder 的输出 pair 第二字。普通调用者先清零 SP270 两字，
把同一地址传给 `1004625c8 -> 1034f78a0`，最后将 SP274 通过 selector 传入网格
tuple 的 B。builder 的 `1034f7dd8` 可以赋值，后续还可按独立字段条件累加
R.f0、R.f8 和 R.16c；较早的未展开调用也接收该 pair。因此 q 不是已知字体 leading，
也不能因调用者曾清零就默认最终为零。

C/D 在 tuple 构造点确实由零初始化，随后网格 helper 可以修改它们。该事实只适用
于这个构造点，不能覆盖下游对齐、尺度协调和显示高度调整。

## 字体高度与聚合边界

字体 wrapper 的 M+8 没有直接复制成这里的 H。默认回调读取 M0/M4，经过条件处理
后重算自己的第三量；LS 再对参与节点的前三项分别取最大值，最后宿主组合前两项
和 content contribution。回调的五字输出与网格 `[H,A,B,C,D]` 是不同记录。

该合同为未来接入提供实际字段来源，但尚未证明真实探针的 provider、模式、字号
单位、E/q 和运行尺度。继续使用显式输入的
[纵向字体参考](FONT-VERTICAL-REFERENCE-2026-09-27.md) 和
[原生网格参考](DOCGRID-ALGORITHM-EVIDENCE-2026-09-27.md)，不把合成输入升级为
文档默认值，也不把 H 直接当成分页 required。
