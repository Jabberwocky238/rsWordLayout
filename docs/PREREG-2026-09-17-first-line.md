Q2 确实判假了。所以本批判的这条**不是看了数据才想出来的**——它在上一批的数据

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 2 记号

```
grid     = 0.24pt
quantize(v) = 四舍五入(v / grid) × grid
natural  = (hhea.ascender + |hhea.descender| + hhea.lineGap) / upem × 字号pt
descent  = |hhea.descender| / upem × 字号pt
正文区顶 = 上边距 = 72pt（本身就在栅格上：72 / 0.24 = 300）
```

## 3 预测

### T0 — 每条基线仍落在栅格上

**判为假**：任何一条基线不是 0.24pt 的整数倍。分母 = **72**。

六个族（Impact / Microsoft Sans Serif / Luminari / Herculanum / Apple Chancery /
Bodoni 72 Smallcaps Book）与前三批**无一重合**，`upem` 有 1000 与 2048 两种，
所以这是第**四**次独立检验。

### T1 — 每页第一条基线（**本批的点预测**）

```
预测 b₀ = quantize(72 + natural − quantize(descent))
```

**判为假的读数**：任何一页的实测 b₀ ≠ 预测值。分母 = **24**（24 组，每组独占一页）。

## 4 对照（**不作预测**，只报得分）

同一批读数上，把已判假的旧形式一并算出来报出：

```
旧形式（accumulation 的 Q2） b₀ = quantize(72 + (ascender + lineGap)/upem × 字号)
```

**这不是候选选择。** T1 是本批唯一的点预测；旧形式只是为了让「新形式有没有比
旧的好」这句话有数可依。**不许因为旧形式分高就改判它成立**——它已经在
accumulation 上判假，要翻案得有它自己的预注册。

## 7.1 判据脚本的修订（**采集之后**，必须看这一节）

第一次采集判 **VOID**，触发 F-B。事后查明那是**量具的缺陷**：判定「申请之外的
字体名」时拿族名做字符串包含，而 `Bodoni 72 Smallcaps Book` 声明的 PostScript 名
是 `BodoniSvtyTwoSCITCTT-Book`，PDF 子集名用的正是 PostScript 名，两者一个字母都不沾。

作废照判，没有例外。随后改的是两处：

1. **采集侧**的字体核查改成读字体文件的 `name` 表（族名 / 全名 / PostScript 名，
   按文件归并），并补上原来没有的一问——**PDF 里有没有账面之外的名字**。
   四种情形独立验过：同一字体拼法不同放行、真替换报警、混进别的字体报警、
   不给文件照旧能用。这一改发生在重采**之前**。
2. **判据脚本**里 F-B 原本自己又算了一遍同样的逻辑，同样的错。现在它
   **直接采信采集包 `META` 里的核查结论**，不再重复实现。

**为什么这不算「看了结果再调判据」：**

- 判据脚本在证否条件触发时**在算 T0 / T1 之前就短路**，`VERDICT.json` 的
  `predictions` 是空的。两次作废里，关于本批预测的数字**一个都没产生过**。
- 改动方向不是放宽而是收紧：新核查比旧的**多**查一类问题。
- T0、T1、容差、分母、排除项、其余证否条件**一个字未动**。

可核：`captures/first-line-2026-09-17-void/` 存着第一次的 `VERDICT.json`，
`predictions` 为空；`git log` 有改动次序。

### T0 成立：栅格第四次独立检验

六个族（Impact / Microsoft Sans Serif / Luminari / Herculanum / Apple Chancery /
Bodoni 72 Smallcaps Book）与前三批无一重合。连上前三批，1/300 英寸栅格现在是
**四份互相独立的夹具、1152 条基线、零例外**。

### T1 不成立

22 / 24。两处不对，**都是 +0.24pt**（实测比预测低一格）：

| 组 | 字体 | 字号 | 实测 | 预测 | 差 |
| --- | --- | ---: | ---: | ---: | ---: |
| t | Apple Chancery | 21pt | 95.52 | 95.28 | +0.24 |
| v | Bodoni 72 Smallcaps Book | 11.5pt | 82.80 | 82.56 | +0.24 |

**新形式比旧形式好（22 对 20），但门槛是全中，所以照样判假。**
「比另一个好」不是成立，把它读成成立就是在做模型选择而不是检验——
这一条在判据文 §4 里采集前就写死了。

### 现在的账

首行这一项试过的两个形式**都判假了**：

- `quantize(72 + (ascender + lineGap)/upem × 字号)`：accumulation 9/12，本批 20/24；
- `quantize(72 + natural − 量化后的 descent)`：本批 22/24。

两者的残差都是**一格**，且本批两处同向（+0.24）。**到此为止，不再往下凑。**
下一个形式要成为判据，得有它自己的预注册和自己的夹具。

### 对引擎的意义

**引擎这一轮不动。** 首行没有确立的规则可落。

引擎当前用的是量化过的 ascent，在 accumulation 采集上给出与 Word 逐位相等
113/240；改成精确 ascent（等价于本批的对照形式）实测降到 108/240，已回退。
两个方向都没有证据支持，就都不进引擎。
