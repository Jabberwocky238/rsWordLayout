## 0 为什么要这一份

上一批（`PREREG-2026-09-17-probe-metrics.md`）**判定 VOID**，作废在 F-E 上：
同一设置连排三段**完全相同**的段落，两个行距不相等，差**恰好一格**（0.24pt）。

F-E 当初是按「量具自检」写的，前提是「两个读数不等 = 测量不稳」。
实际发生的是另一回事：**被测的那个量本来就不是常数。**
于是上一批五条预测的共同前提——「每种设置有**一个**行距」——塌了，五条一起废。

这一份改判**位置**，不判**行距**。

## 1 容差

**0.0000pt。** 逐位相等，不是「接近」。唯一例外：PDF 读数的十进制舍入，
取 **1e-6 pt** 的数值容差，仅用于吸收浮点表示，不吸收任何真实差异。

## 2 预测

记 `grid = 0.24pt`（1/300 英寸），`quantize(v) = 四舍五入(v / grid) × grid`，
`natural = (hhea.ascender + |hhea.descender| + hhea.lineGap) / upem × 字号pt`。

### Q0 — 每一条基线都落在栅格上

**判为假的读数**：任何一条基线的 y 不是 0.24pt 的整数倍。
分母：采集到的全部基线 = **240**（12 组 × 20 行）。

上一批已经是 78/78，但那 78 条全部来自 Liberation 三兄弟与 Carlito。
这一份换了五个族，**没有一个是上一批任何一个的度量克隆**，所以它是独立检验，
不是同一批证据再数一遍。

### Q1 — 累加律：细累加，落位量化

以每页**实测的第一条基线** `b₀` 为锚：

```
预测第 n 条基线 = quantize(b₀ + n × natural)      n = 1 … 19
```

这就是「Word 按**未取整**的自然行高累加游标，每条基线**落位时**才量化到栅格」。
它预言的相邻基线之差会在相邻两个栅格值之间**交替**——也就是上一批 F-E 撞见的东西。

拿实测的 `b₀` 当锚，是把首行那一项**当已知条件**给出去，好让这一条只判累加律本身；
首行那一项单独由 Q2 判。**一条预测只判一件事。**

**判为假的读数**：任何一条基线 ≠ 预测值。
分母：**228**（12 组 × 19 步）。

### Q2 — 每页第一条基线

```
预测 b₀ = quantize(正文区顶 + (hhea.ascender + hhea.lineGap) / upem × 字号pt)
```

正文区顶 = 上边距 = 72pt（本身就在栅格上：72 / 0.24 = 300）。

**判为假的读数**：任何一页的实测 `b₀` ≠ 预测值。分母：**12**。

> 上一批这一项没对上（按同一形式算 78 条基线只中 39 条，差的全是一格）。
> **若 Q2 判假，下一个待判的形式是** `quantize(正文区顶 + natural − 量化后的 descent)`
> ——即上一批 P2 的形式。**这不是本批的预测**，写在这里，是为了让下一份预注册
> 不是「看了数据才想出来的」（§7.1）。

## 3 采集前声明的排除项

某一组的 20 段**没有全部落在同一页上**时，该组的 Q1 / Q2 读数**判不了**，
记入分母但不算通过（§8 的口径排除，不是放宽容差）。累加从每页顶重新开始，
跨页的差值不是累加量。

夹具给每组都加了 `w:pageBreakBefore`，且最大字号 22pt 下 20 行只占 ~495pt，
远小于正文高 698pt，所以正常排版下这条不该触发。触发了会原样打印出来。

## 5 采集条件

  §6.6：Mac 与 Windows 是两套字体度量，本批结论只能写「在 Mac Word

### Q0 成立

**240 / 240。** 五个族——Georgia / Verdana / Tahoma / Comic Sans MS / Trebuchet MS——
没有一个是上一批任何一个的度量克隆，所以这是一次**独立检验**，不是同一批证据再数一遍。
连上一批的 78 / 78，1/300 英寸纵向栅格现在是这套东西里证据最硬的一条。

### Q1 不成立，但差得很有形状

193 / 228。**35 处全部差 −0.24pt，一步不多一步不少**——没有一处差两格，也没有一处
差别的量。逐组看：

| 组 | 字体 | 字号 | Q1 |
| --- | --- | ---: | ---: |
| A17 / A30 / A34 / A44 | Georgia | 8.5 / 15 / 17 / 22 | **19/19** |
| B2 / B3 | Tahoma / Comic Sans | 13 | **19/19** |
| B4 | Trebuchet MS | 13 | 17/19 |
| B1 | Verdana | 13 | 16/19 |
| A21 / A40 | Georgia | 10.5 / 20 | 13/19 |
| **A26 / B0** | **Georgia 13pt（同一设置，两组）** | 13 | **10/19、10/19** |

A26 与 B0 是同一字体同一字号的两组，**两组给出完全相同的 10/19**。
所以这些不对不是噪声，是**可复现的**——量具与 Word 在这一层上都是确定性的，
对不上的是模型。

### 已经能排除的两种解释（都不是拟合，是算术）

**不是读错了度量表。** 五个族的 `hhea` 与 OS/2 的 `winAscent/winDescent` 完全相同，
而 OS/2 的 `sTypo` 系列差了约 6%。若 Word 读的是 sTypo，19 步累计的偏差会是
好几格，几乎处处不对，而不是 228 步里错 35 步。

**也不是四舍五入的进位规则。** 把每一步的精确位置除以 0.24 取小数部分：
35 处不对的**全部** > 0.5（我进位了，Word 没进）——可是**对上的里面也有 67 步 > 0.5**。
所以「Word 一律截断」同样解释不了。规则不在这一层。

### 探索性（§7.5 标「回测」，**不当独立检验**）

剩下的形状指向：Word 的游标大概不是在实数上累加 `n × 自然行高`，
而是在某个**更细的整数单位**上走，每步各自定位。那个单位是什么，本批判不了。
**到此为止，不再往下凑。** 要成为结论，得写新的预注册、采新的夹具。

### Q2 不成立

9 / 12，三处差 ±0.24：Georgia 20pt（+0.24）、Verdana 13pt（+0.24）、
Comic Sans MS 13pt（−0.24）。**方向不一致**，所以不是一个固定偏置。

按本文 §2 采集前的声明，下一个待判的形式是
`quantize(正文区顶 + natural − 量化后的 descent)`。**本批不判它**——
那要新的一份预注册和新的一份夹具。

### 净收获

- 栅格：又一次独立检验，240/240。**这一条可以当作已确立的了。**
- 「细累加、落位量化」的**大方向对**：228 步里 193 步逐位相等，且错的全是一格。
  上一批那个「每行各自取整」的模型在这份夹具上只能拿 37/228（合成自测），
  两者已经分得很开。
- 但**还不够精确到可以写进引擎**。引擎现在落到整 twips，本批说明就算把
  分辨率提到 1/300 英寸也还差一层——那一层是游标本身的单位。
