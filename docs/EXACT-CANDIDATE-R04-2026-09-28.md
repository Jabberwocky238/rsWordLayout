# R04 exact 候选：最早分歧、排除的候选与预登记的判别集（2026-09-28）

本片执行 [北极星规划](NORTH-STAR-AND-ROADMAP.md) 的 R04：选定一个规范 exact 候选合同，用全部
12 例报告最早分歧，闭合它依赖的一个输入或以反例排除它。材料是
[规范 exact 反例](EXACT-VERTICAL-EVIDENCE-2026-09-27.md)里的 12 例 Word 采集和 113 条历史首行。
没有运行 Word，引擎行为也没改；只读冻结的证据，写了评估脚本、判别夹具和预登记的预测。

## 做法

单位 u = 1/300 英寸 = 4.8 twips = 0.24 pt，L = exact 值 / 4.8，t = 行顶 twips（页边距加前面各行 exact，
连续累加），R = 四舍五入、远离零。观测量是每行正文首字形（或段落标记）的 PDF 原点 y。

候选先写进假设文件、算哈希，再跑评估；数据此前已经读过，所以 K2、K3 都是回测：

| 候选 | 公式 | 来源 |
| --- | --- | --- |
| K1 | y_u = R(t/4.8 + R(R(L)·4/5)) | 已登记的固定 300 候选，推到后续行（连续游标） |
| K2 | y_u = R(R(t/4.8) + L − ⌊L/5⌋) | 本片看过数据后推的 |
| K3 | d = R(L) − R(0.8L) − R(0.2L)；y_u = R(t/4.8 + R(0.8L) + max(0, d)) | 本片看过数据后推的，结构取自冻结的高度调和模型 |

## 这一轮缩小了什么

历史行的行顶都是整格，所以它们只约束偏移 C = y_u − t/4.8，而 C 只随 exact 值变：

- C 与 R(0.8L) 只在 exact ≡ 8 (mod 24)（L 小数部分为 2/3）时不同，那时 Word 多一格：248、272、296、320；
- 0.8L 小数部分为 1/3 的 51 行里，是否多一格与字体（Luminari、Brush Script、Silom、Lao Sangam）和
  字号（8–30 pt）都无关，只看 exact 值；
- 于是**任何「先对 L 做单调取整、再乘 0.8 取整」的规则都不成立**：248 要求向上，而 206、194 要求不向上。
  能拟合出来的式子（例如 0.3L + 0.5R(L)）没有来由，按路线图不用。

K3 的「+1」来自冻结调和模型里的机制：两套尺度下，总量与分量分别取整，差额为正时加给一个分量，
为负时先由外侧分量吸收。K3 只借用这个**结构**。模型里字段的角色（Fb8 / Fc0 / Fc8 / Fd8 各是什么，
正差额给 B 还是给 4/5 部分）、宿主实际用的尺度对 (S0, S1) 以及指针是否相同，都**没有绑定**。
S=300 仍然是假设。
