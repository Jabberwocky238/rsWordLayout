## 2 预测

### Q0 — 每条基线仍落在栅格上

分母 = 采集到的全部基线。第**二十**次独立检验。

### Q1 — 抬升量**量化到栅格**

```
y_normal − y_raised = quantize(val / 2)        quantize 到 0.24pt，半数进位
```

`w:position` 取 **10 / 14 / 24 / 26 / 48** 半点，与第一版的取值**全换**
（第一版作废于 F-B，见 §5.1）。刻意让一半落在整格上、一半落不上：

| `val` | pt | 格 | 整格？ |
| ---: | ---: | ---: | --- |
| 10 | 5.0 | 20.833 | **否** |
| 14 | 7.0 | 29.167 | **否** |
| 24 | 12.0 | 50 | 是 |
| 26 | 13.0 | 54.167 | **否** |
| 48 | 24.0 | 100 | 是 |

**判为假的读数**：任何一个不等。分母 = **5**。

> 半数进位这个方向取自 vmisc 的读数（`val=6` 实测 3.12 = 13 格，向上），
> 属**已见数据**，按 §7.5 记为**线索不独立**。但取值全换了，
> 而且三个非整格值一起判，不是拿一个点凑。

### Q2 — 同一行内，不同字号**共用一条基线**

每行三段 run：小字号、大字号、小字号。三种字号组合
（10/20pt、13/26pt、8/30pt）。

```
同一行内所有字形的 y **完全相同**
```

**判为假的读数**：任何一行内有两个字形 y 不同。分母 = **3**。

### Q3 — 分页符按位置画 0 或 1 个字形

三种位置各一组（§4 的三分）：**独占一段** / **紧跟段落标记** / **段中**。

判的是**量具的计数模型与实测字形数对得上**：`wordmodel` 给出的每条行记录
状态都是 `OK`（不是 `COUNT_MISMATCH`，也不是判不了）。

**判为假的读数**：任何一条涉及分页符的行记录状态不是 `OK`。
分母 = 这三组涉及的行记录数。

## 5 采集条件

- **Mac**，Word for Mac，**兼容性模式**。
- 申请字体：`Luminari` **与 `Times New Roman`**。

### 5.1 为什么要申请 `Times New Roman`

第一版夹具采集后作废于 F-B：PDF 里出现 `TimesNewRomanPSMT`。查清楚了——
**Times 只出现在空格字形上，而且只在「只含 `w:br` 的那个段落」的段落标记处**。
那种段落没有任何可见 run，Word 就拿**默认字体**画它的段落标记，
`w:pPr/w:rPr` 里指定的字体管不住。

**那一组不能改。** 「整段只有一个分页符」正是 §4 三分里的第一种；
在它前面加可见文字，它就变成第二种「紧跟段落标记」，三分塌成两分。

所以改的是**申请清单**：把 `Times New Roman` 列进去，理由就是上面这条——
**它是 Word 画空段落标记时必然会用的字体，不是替换**。

这不是放水：F-B 仍然会报**任何其他**账外字体。
放宽的只是一个已经查清原因的、可预期的名字。

**第一版的作废照记**，不追认。判据脚本在算 Q1/Q2/Q3 之前就短路，
`predictions` 是空的，所以换取值重采不构成「看了结果再调」。

## 6 结论

采集包：`captures/vmisc2-2026-09-17/`。Word for Mac，11 页，88 字形，
四条证否条件一条都没触发。

| | 判据 | 结果 | |
| --- | --- | ---: | --- |
| **Q0** | 每条基线落在栅格上 | **8 / 8** | **成立** |
| **Q1** | 抬升量 = `quantize(val/2)` | **5 / 5** | **成立** |
| **Q2** | 同一行内各字号共用一条基线 | 2 / 3 | **判不了** |
| **Q3** | 分页符计数模型对得上 | 1 / 1 | **成立，但分母只有 1** |

### Q1 成立：抬升量确实被量化到栅格

五个 `w:position` 值全中，其中**三个不落在整格上**：

| `val` | pt | 格 | 量化后 |
| ---: | ---: | ---: | ---: |
| 10 | 5.0 | 20.833 | 21 格 |
| 14 | 7.0 | 29.167 | 29 格 |
| 24 | 12.0 | 50 | 50 格 |
| 26 | 13.0 | 54.167 | 54 格 |
| 48 | 24.0 | 100 | 100 格 |

这与 V1（基线都在栅格上）是一回事：抬升后的字形 y 也得落在栅格上，
所以抬升量**必然**是 0.24 的整数倍。vmisc 的 P2 之所以在 `val=6` 上失败，
就是因为 12.5 格落不上去。

**但线索不独立**（进位方向取自 vmisc 的读数，判据文 §2 已声明），
按 §7.5 只算**初步成立**。

### Q2 判不了

三组里一组（8pt / 30pt 混排）不是恰好一行，按 §3 排除。
另两组的行内各字号**确实共用一条基线**，但 2/3 不满足「全中」，所以判不了。

### Q3 的分母只有 1——这才是这一项真正的结果

含分页符的**三页全部归行判不了**，原因是 `PAGE_COUNT_MODEL_INCOMPLETE`：
**量具自己的计数模型在分页符这几种情形下给不出确定的预期字形数**。

所以「Q3 成立」这句话没有分量：能判的只有 1 条行记录。
**真正被这一批量出来的是量具的缺口，不是 Word 的规则。**

C3（分页符三分）因此仍然**未决**，而且现在知道它卡在哪：
要判它，得先把 `counting` 的分页符分支补完整——那是量具的事，不是 Word 的事。
