# 预注册：`lineRule="auto"` 下的自然行高是哪一组字体量

日期 2026-09-18。判据在看任何得分**之前**写死（§7.1）。

## 0 为什么现在能判

W-2 一直写着「要证实或推翻，需要一份**专门变字号与字体**的夹具，本仓库还没有」。
**那种夹具一直在采集包里**，只是分散在九份走 `lineRule="auto"` 的采集上：
`accumulation`、`baseline-order`、`cursor-unit`、`first-line`、`hbox`、`hbox2`、
`indent-align`、`page-start`、`probe-metrics`。

清点之后：**100 个 (字体, 字号) 组、125 页、27 种字体、字号 6.00–35.04pt**。
W-2 当初只有 **2 个点**。

**不需要开 Word。** 全部读数来自既有采集包。

## 1 已经看过什么、没看过什么

按 §7.5 如实写在前面：

- **看过**：上面那张分母表，以及各组实测的行距值本身
  （例如 BrushScriptMT 29.04pt 的行距是 46.08 / 46.32pt）。
- **没看过**：下面任何一个候选在任何一组上的得分。候选全部是**有名字的字体量组合**，
  不含任何拟合出来的常数——没有「调一个系数去凑」的余地。
- 为了让它仍是一次真检验，数据**在评分之前**切成两半，界线写死在本节：
  - **判定集**：`page-start` 的 6 种字体 × 3 个字号 = **18 组**
    （AppleMyungjo / ArialUnicodeMS / BrushScriptMT / KhmerSangamMN / LaoSangamMN / Silom，
    29.04 / 33.12 / 35.04pt）。
  - **保留集**：其余 **82 组**，21 种字体。**判定集评完、结论写下之后**才评。
    判定集上通过、保留集上不通过的候选，按判假处理。

## 2 量什么

每页取该页全部基线，按升序排。**行距的估计值**取

```
step_est = (最后一条基线 − 第一条基线) / (行数 − 1)
```

不取相邻差：相邻差被 V18 的落位量化切成了两个相差一格的值（实测每组都是
`[x, x+0.24]` 这种形状），而端点之差把量化误差摊到 n−1 个间隔上。

**判定容差**因此取量化本身的界：

```
|step_est − 候选值| ≤ 0.24 / (行数 − 1)
```

这是 `c(n) = ⌊A + n·step⌋`（V18，已确立）能造成的最大偏差，不是放宽的容差。
行数 < 3 的页不进分母。

## 3 候选（全部按 `值 / upem × 字号pt` 折算）

| 代号 | 式子 | 来源 |
| --- | --- | --- |
| **N1** | `(hhea.ascender − hhea.descender + hhea.lineGap)` | **引擎当前用的**（skrifa `metrics()` 默认走 hhea） |
| **N2** | `(OS/2.usWinAscent + OS/2.usWinDescent)` | Windows 的行高传统 |
| **N3** | `(OS/2.sTypoAscender − OS/2.sTypoDescender + OS/2.sTypoLineGap)` | OpenType 排版量 |
| **N4** | `max(N1, N2)` | 两者取大 |
| **N5** | `(hhea.ascender − hhea.descender)` | N1 去掉 lineGap |
| **N6** | `(OS/2.usWinAscent + OS/2.usWinDescent + hhea.lineGap)` | N2 加 lineGap |

每个候选另配一个**量化变体**（值先按 0.24pt 栅格四舍五入），记作 `N*q`。

## 4 判定

- 一个候选在判定集上 **18/18** 成立才算通过；任何一组不成立即判假。
- 判定集上通过的，再到保留集上评，**82/82** 才算成立；否则判假，并记下它在哪一族上败。
- 全部判假时，结论是「这六个都不是」——**不再拿数据去凑第七个**（§7）。

## 5 证否条件（先写死）

| | |
| --- | --- |
| **F-α** | 同一 (字体, 字号) 组在不同采集包上给出不同的 `step_est`（超出容差）。量具或采集不可信 |
| **F-β** | 某组的行距不是 0.24pt 的整数倍。V1 已确立，违反即读数有问题 |
| **F-γ** | 判定集全体通过而保留集全体失败。切分本身出了问题，不是候选的性质 |

## 6 范围限定

- **Mac Word 16.112**，全部读数来自 2026-09-17 那一批采集（§6.6：不可外推到 Windows）。
- 只判 `w:lineRule="auto"` 且 `w:line="240"`（单倍）。其它倍数未测。
- 段落间距一律 `before=0 after=0`，所以量到的是**行距**不是段距。
- 不含 CJK 正文（27 种字体里有 CJK 字体，但正文都是拉丁字符）。

# 7 判定（2026-09-18，评完之后写）

## 7.1 判定集（18 组）：**六个候选全部判假**

| 候选 | 成立 | 量化变体 |
| --- | ---: | ---: |
| **N1**（引擎当前用的） | **9/18** | 4/18 |
| N2 | 0/15 | 0/15 |
| N3 | 3/15 | 2/15 |
| N4 | 6/15 | 4/15 |
| N5 | 6/18 | 2/18 |
| N6 | 0/15 | 0/15 |

按 §4，判定集不到 18/18 即判假。**六个都判假。**

**但 N1 的失败方式是有结构的**：18 组里 9 组**逐组吻合**（误差 ≤ 0.013pt），
另外 9 组的比值**恒为 1.300**：

| 字体 | 实测/N1（三个字号） |
| --- | --- |
| AppleMyungjo | 1.30044 / 1.30064 / 1.30051 |
| ArialUnicodeMS | 1.30022 / 1.30025 / 1.30044 |
| BrushScriptMT | 1.29981 / 1.30000 / 1.30005 |
| KhmerSangamMN / LaoSangamMN / Silom | 0.9998 ~ 1.0000 |

**第一次算的时候这九组也是错的，错在我这边**：字号取了 PDF 的 `effectiveSizePt`，
而那是 **H7 那个被量化过的画字字号**（29pt 画成 29.04）。换成夹具里的真字号之后，
比值才从 1.2986 收敛到 1.3000，另外九组才从「差 0.09pt」变成「差 0.01pt」。
**H7 因此多了一条独立用途**：拿 PDF 的字号去算任何纵向量，都要先换回真字号。

## 7.2 保留集（82 组、26 种字体）回测

比值中位数：**25 种字体 ≈ 1.000**，只有 `LiberationSerif` 的 6 页落在 0.69–0.81
（那 6 页是 `probe-metrics` 的 `w:position` 抬升页，基线被抬升量推着走，
算出来的不是行距——**预注册没把它们排除，是我漏了**，按 §7 仍计入分母）。

## 7.3 那 ×1.3 是什么（**回测，证据是相关不是机制**）

试过并**排除**的判别式：

| 试过的 | 结果 |
| --- | --- |
| `hhea.lineGap == 0` | **排除**：LaoSangamMN / Silom 的 gap 也是 0，却是 ×1.0 |
| 字体包围盒 `head.yMax − yMin` | **排除**：它把 N1 已经算对的六种全弄错（比值 0.69~1.24） |
| `usWinAscent/Descent` 与 `hhea` 逐位相同 | **排除**：19 种字体反例（Georgia、Luminari、Impact… 都相同却是 ×1.0） |

**成立的**：`OS/2.ulCodePageRange1` 的第 **17–21** 位（JIS/日、简中、韩 Wansung、
繁中、韩 Johab）任一置位，**或该字体根本没有 `OS/2` 表**。

| 组 | 字体数 | 东亚代码页 |
| --- | ---: | --- |
| ×1.3 | 3 | ArialUnicodeMS（五位全置）、BrushScriptMT（简中＋韩 Johab）、AppleMyungjo（**无 OS/2 表**，只有 `bdat`/`bloc` 的老式 Apple 字体） |
| ×1.0 | 29 | **一种都没有**，且全部有 OS/2 |

**32 种字体零例外。** `BrushScriptMT` 是拉丁手写体却进了 ×1.3 组——
判别的是**字体声明了什么代码页**，不是字体画的是什么文字。这一条是这批里最要紧的证据：
任何「按脚本判」的解释都被它排除了。

## 7.4 由此得到的候选 N7（**回测，不算独立检验**）

```
自然行高 = (hhea.ascender − hhea.descender + hhea.lineGap) / upem × 真字号
           × (1.3 若字体声明东亚代码页或无 OS/2 表，否则 1.0)
```

**118/125 页成立**（容差同 §2）。不成立的 7 页：

- 6 页是 §7.2 那批 `w:position` 抬升页（范围外，但预注册没排除，照算）；
- 1 页是 `page-start` p26，AppleMyungjo 33pt，实测 50.9600 / 预测 50.9359，
  差 0.0241pt 而容差 0.0200——**差 1/10 个栅格**。该字体 upem = 1025（非 2 的幂），
  是唯一一个没有 OS/2 表的，单独记着。

东亚组的实测系数落在 **1.29924 ~ 1.30062**（18 页），中位 1.30020。

## 8 这条结论的身份，以及它已经预测到了什么

**N7 是回测**（§7.5）：判别式是看过数据之后找出来的，不是预注册里的候选。
要确立，需要一份**专门按代码页位分组**的新夹具——同一个脚本的字体，
一半声明东亚代码页、一半不声明，看行高是否跟着代码页走而不是跟着脚本走。
**那需要开 Word 采集，本次没做。**

**但它已经在解释东西了**：引擎用的就是 N1，**不带那个 1.3**。所以

| | 引擎 | N7 预测的 Word |
| --- | ---: | ---: |
| `fixtures/plain.docx`（中文，走 SimSun/回退到 DroidSansFallback） | 行距 **15.60pt** | **20.41pt** |

**差 31%。** 该夹具引擎排 3 页 90 行——若 N7 成立，Word 会排成 4 页。
这是 CJK 那条路上第一个**有数的**预测，此前只有「未测」。

顺带：`fixtures/plain.docx` 第一次跑了 `selfcheck`，**四条全 OK**
（字形层覆盖、源区间是全篇偏移、终止符自洽、一行一条记录）。
CJK 这条路的轨迹契约本身没问题——差的是量它的那一半。
