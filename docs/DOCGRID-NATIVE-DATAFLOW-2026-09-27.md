# docGrid 原生输入与消费者映射

本片在已恢复的整数 helper 两侧补数据流，目标是把算术接到可识别的字体、段落和
分页合同。当前已确认新旧路径的周期/尺度来源及普通分支的 LS 参数映射；尚未取得
运行时模式，也没有把中间字段直接当作字形基线或页面 required。

全部证据来自离线 arm64 指令及文件读取，没有启动、附加或操作 Word，没有执行
原生函数、采集新文档或修改生产算法。宿主为 Word 16.112.3 / 16.112.26083020，
SHA-256 `b569d257c22eb75b990ff8212b75c734ae20f51e9dacc9ccc509c988a6e0d52c`。
地址为未加运行时 slide 的 Mach-O 虚拟地址，PTLS 框架基址为零。

## 周期和尺度共享来源

用 P 表示行高适配器取得的父对象，T 表示旧路径线程上下文。

| 新路径输入 | 已证明的来源 | 证据位置 |
| --- | --- | --- |
| P+140/+144/+148 | 三个 word：mode、第一尺度、第二尺度 | `0x1003391f8` 转换与 `0x100339298` 写入 |
| helper 尺度 S=P+148 | slot `0x10472c620` 所指对象的 +18c，mode2 有规范常量例外 | `0x100339020` 构造调用链 |
| 周期 P+b8 | T+8ea0 的 i32 原样复制 | `0x10033856c`、`0x100338620`、`0x100a74a94` |
| 选择值 P+b0 | T+8ea4 的 u16 零扩展 | 同一复制链；`0x10003a0d8` 是单条 ret |
| P+b4 | T+8e85 的 u8 转为非零布尔值 | 同一复制链 |

尺度转换器对 modes 0/1/3 复制原对象的两个尺度。mode2 检查它们是否为 294912，
不等时发出诊断，但无论如何都返回只读 `{2,294912,294912}`。因此不能将错误分支
也描述为原样复制。正常 mode2 与旧路径同源；没有测得本批探针实际使用的 mode。
P+14c/+150/+154 是 slot628 对应的另一组三 word，不能和第一组混用。

构造 P+1c0 请求时，两个三位 selector 来自 P+228 所指 owner 的 +26c 位 8..13。
它们和上述两位 mode 不是同一枚举。另有输入来自 owner+6c 的低十位及 owner+64c；
公开类型和字段写入者尚未知，不能据邻近的 `pct` 诊断文字命名为 zoom、DPI 或 view。

周期所在缓存块的实际复制边已闭合，公开 `w:docGrid`、`linePitch` 与 sprm 写入
尚未闭合。后续入口是 `0x1000d875c -> 0x1000d87ac` 和
`0x102ca819c -> 0x102ca80bc`；相同偏移或旧报告中的拟合常数不能补上属性身份。

## 中间分量到 LS 四参数

令纯 helper 输出前五个 word 为 `[H,A,B,C,D]`。这是位置命名，尚不表示字体表字段。
正常适配分支（R+1a8 的 bit0 为零）写入：

```text
R.d0=H       R.c8=B       R.c0=A+C
R.d8=C       R.e0=D       R.b8=H+B+C
```

若 slot620/slot628 中存储的两个指针相等，且后续清零/可选 hook 未改变这些值，
`0x103668ac4..0x103668ae8` 的复制和差分抵消掉 C、B。最终经宿主
`0x100379ef4` 转发到 `LsModifyLineHeight` 的四个整数依次为：

```text
[B, H-A, A, C]
```

| LS 参数序号 | 格式主子行存储 | 显示主子行存储 | 上述条件下的值 |
| --- | --- | --- | --- |
| 0 | +15c | +84 | B |
| 1 | +190 | +78 | H-A |
| 2 | +194 | +7c | A |
| 3 | +160 | +80 | C |

`CLsDisplayMainSubline::Create` 的初始化路径独立印证了这一排列：它读取格式对象的
两对字段，将后一对反序后写入显示对象。这是可核对的跨对象存储关系，不是根据
Word 输出反推的公式。

当两尺度指针不等时，宿主分别转换两个差分与 B/C/D，再按单独转换的总量分配余数。
上面的简式不覆盖该分支。指针相等也不能由静态初始地址或零填充数据推定为运行事实。

## 尚未闭合的最终消费

`LsGetObjDimSublineCore` 有读取格式对象 +190/+194 的具名 `heights` 查询路径，
但修改这两个字段会设置 +1b4 的 bit0x200，该缓存路径恰好要求此位清零。因此，
不能把静态读回边当作每次修改后的即时最终高度；缓存刷新和回退聚合仍需核对。

`LsDisplayLineNew` 接收宿主提供的点，并可能做 LSDEVRES 转换后调用绘制回调。
本片没有将该点的来源或上述四字段接到最终 PDF glyph origin。同样，R.b8 的
中间总量 `H+B+C` 尚未通过 PTS 的分页消费者证明为 required extent。

后续应分别闭合字体/LS 聚合、宿主显示点、PTS 行高返回及尺度选择，不把一个总量
同时填入基线、推进和占高。现有引擎的三个通道继续独立，网格状态仍为未应用。
