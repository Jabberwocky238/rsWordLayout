## 0 要判什么

shift-floor 立住了一件事：位置是某个连续量的截断，`c(n) = ⌊A + n × step⌋`
（16/16）。同一批的**回测**还撞见：同一 `w:line` 下换字体，基线**逐格相同**，
连首行都一样（8/8）。那两个族的 ascent 是 1820/2048 em 与 891/1025 em。

回测不算数。本批独立检验它，而且用差得**更极端**的族：

| 族 | upem | ascent | ascent / upem |
| --- | ---: | ---: | ---: |
| Zapfino | **400** | 750 | **1.875** |
| Trattatello | 1000 | 1150 | 1.150 |
| Khmer Sangam MN | 2048 | 2294 | 1.120 |
| Luminari | 1000 | 983 | 0.983 |
| AppleMyungjo | 1025 | 891 | 0.869 |
| Herculanum | 1000 | 795 | **0.795** |

跨度 **2.4 倍**。Zapfino 在 13pt 下 ascent 有 **24.4pt**，比本批最大的行距
（14.6pt）还高——若字体真的不参与，连它也该落在同一格上。

## 1 容差

**0.0000pt**，逐位相等。位置用有理数与整数格数算，不沾浮点。

## 2 预测

### W0 — 每条基线仍落在栅格上

分母 = **240**。第**十一**次独立检验。

### W1 — 点预测：`exact` 行距下，基线位置与字体无关

对每个 `w:line`、每个行序号 `n`（0 … 9），六个族给出的基线格数**全部相同**。

**判为假的读数**：任何一个 (`line`, `n`) 上六个族不全相同。
分母 = **40**（4 个 `line` × 10 个行序号）。

- **成立** → `exact` 下字体完全不参与纵向定位，**连首行都不参与**。
  这会把 V7（首行形式）在 `exact` 场景下整个消掉：没有字体量可算，
  A 就只能是 `line` 的函数。
- **判假** → 字体参与，那 shift-floor 的那个回测是巧合，
  而 A 的形式里必须含字体量。

## 3 另报（**不作预测**）

各 `line` 的 A 区间，以及 A 是否只依赖 `line`。供下一批写 A 的形式用。

## 4 采集前声明的排除项

某组的 10 行没有全部落在同一页上时，该组涉及的 (`line`, `n`) **判不了**，
记入分母但不算通过。最大行距 14.6pt × 10 行 = 146pt，远小于正文高 698pt。

## 5 证否条件（量具自身）

F-A 采前核查 / F-B 字体核查 / F-C 夹具 sha256 / F-D 页数不符。

## 6 采集条件

- **Mac**，Word for Mac，**兼容性模式**。
- 字体族：`Zapfino` / `Trattatello` / `Khmer Sangam MN` / `Luminari` /
  `AppleMyungjo` / `Herculanum`（Word 自己列出来的名字）。
- **标签只用字母与数字，且生成时用 `cmap` 核过**：Kokonor 那次教训是，
  字体画不出标签，Word 会静静换回退字体，整批作废。

## 7 结论

采集包：`captures/font-free-2026-09-17/`。Word for Mac，24 页，720 字形，
四条证否条件一条都没触发。

| | 判据 | 结果 | |
| --- | --- | ---: | --- |
| **W0** | 每条基线落在栅格上 | **240 / 240** | **成立** |
| **W1** | `exact` 下基线位置与字体无关 | **40 / 40** | **成立** |

### W1 成立：字体一点都不参与

六个族的 `ascent / upem` 从 0.795 到 1.875，差 **2.4 倍**；
Zapfino 在 13pt 下 ascent 有 **24.4pt**，比本批最大的行距 14.6pt 还高。
40 个位置上，六个族给出的基线格数**全部相同**。

各 `line` 的 A 区间也逐族一致：

| `w:line` | A mod 1（六族一致） |
| ---: | --- |
| 222 | [0.5000, 0.7500) |
| 244 | [0.1667, 0.3333) |
| 256 | [0.3333, 0.6667) |
| 292 | [0.3333, 0.5000) |

**这把 V7（首行形式）在 `exact` 场景下整个消掉了**：没有字体量可算，
A 只能是 `w:line` 的函数。

### 对引擎的意义：这一条**直接改**

引擎的 `line_height_fine` 对每种行距规则都套了一个「内容下限」
（`.max(ascent + descent)`），于是 `exact` 下行高会被字体撑开——
Zapfino 那一组的行距会变成 24.4pt 而不是 11.1pt。**W1 40/40 说 Word 不这么做。**

已改：`exact` 直接返回 `w:line`，不受内容下限约束。`atLeast` 与 `auto` 不动。
回归测试两条：一条钉住「字比行高也不撑开」，一条自证鉴别力
（同样输入换 `atLeast` 必须被撑开，否则把 `exact` 写成恒返回 `w:line` 也能全绿）。
回退修复，前者转红。
