## 0 为什么转到横向

纵向查了十四批，V19（A 的形式）暂时卡住：固定比例、固定距离、以及任何线性
`T + k·L` 都已排除，而在想出**有原理**的下一个候选之前，接着猜只是烧采集。

横向这边至今只有一条结论（H1：推进量取自字体、`w:kern` 默认关，Δx 中位 0.0000pt）。
**缩进与对齐一次都没变过**——前十四批一律左对齐、零缩进，
正是 §7.2 警告的「这一维只有一个实例」。

## 1 两条预测都**不依赖字体度量**

这是本批能判得干净的原因。

### 缩进
左对齐时行首字形的 x 与字宽无关：

```
x = 72pt + w:ind/@left            （非首行）
x = 72pt + @left + @firstLine     （首行，@firstLine 可负 = 悬挂）
```

### 对齐
同一段文本在左 / 居中 / 右三种对齐下，行宽 `w` 是**同一个数**，而

```
x_center = x_left + (avail − w) / 2
x_right  = x_left + (avail − w)
```

两式相减消去 `w` 与 `avail`：

```
x_right − x_left = 2 × (x_center − x_left)
```

**不必知道行宽，也就不必算字形推进量。**

## 2 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 3 预测

### G0 — 每条基线仍落在栅格上

分母 = 采集到的全部基线。第**十五**次独立检验。

### G1 — 缩进：行首 x = 72pt + 左缩进（首行再加首行缩进）

八组 `(左缩进, 首行缩进)`，含两组**悬挂**（首行为负）：
`(0,0) (360,0) (720,0) (1080,0) (0,360) (360,720) (720,−360) (1440,−720)` twips。

**判为假的读数**：任何一行的首字形 x ≠ 预测值。分母 = **16**（8 组 × 2 行）。

### G2 — 对齐：`x_right − x_left = 2 × (x_center − x_left)`

四段长短不同的文本（2 / 8 / 16 / 24 字符），各排三种对齐。

**判为假的读数**：任何一段的等式不成立。分母 = **4**。

## 4 另报（**不作预测**）

各段的 `avail − w`（= `x_right − x_left`），以及居中时的余数是否恰好半分。

## 5 采集前声明的排除项

某段换了行（不止一行）时，该段**判不了**，记入分母但不算通过。
文本最长 24 字符，13pt 下远小于正文宽。

## 8 结论

采集包：`captures/indent-align-2026-09-17/`。Word for Mac，20 页，262 字形，
四条证否条件一条都没触发。

| | 判据 | 结果 | |
| --- | --- | ---: | --- |
| **G0** | 每条基线落在栅格上 | **28 / 28** | **成立** |
| **G1** | 行首 x = 72pt + 左缩进（+ 首行缩进） | **16 / 16** | **成立** |
| **G2** | `x_right − x_left = 2 × (x_center − x_left)` | 0 / 4 | **不成立** |

### G1 成立：缩进这一项定了

八组 `(左缩进, 首行缩进)` 共 16 个 x 读数**全中**，包括两组**悬挂**
（首行缩进为负：`(720, −360)`、`(1440, −720)`）。
行首 x 就是 `72pt + @left + @firstLine`，与字宽无关。

### G2 不成立，但失败得很整齐

四段文本（2 / 8 / 16 / 24 字符）的差**完全相同**：

| 文本 | 右 − 左 | 2 ×（中 − 左） | 差 |
| ---: | ---: | ---: | ---: |
| 2 字符 | 420.1265 | 419.8925 | **+0.2340** |
| 8 字符 | 383.6362 | 383.4024 | **+0.2338** |
| 16 字符 | 328.8290 | 328.5952 | **+0.2338** |
| 24 字符 | 272.4358 | 272.2017 | **+0.2341** |

行宽从 31pt 变到 179pt，差值纹丝不动。**这不是按比例的偏差，是一个固定量。**

换算过来：居中位置比理论中点**偏左 0.117pt**（= 0.234 / 2），
而这个偏移与行宽无关。右对齐没有这个偏移——它与左对齐的差正好是整个余量。

### 探索性（§7.5 标「回测」，**不当独立检验**）

固定 0.117pt 的偏移解释不了成「余量减半时取整」——那样的残差会随行宽变，
而实测四段一模一样。更像是**居中的基准点本身**比左右对齐所用的少 0.234pt。

**到此为止，不再往下凑。** 居中的形式要成立，得有它自己的预注册和自己的夹具。

### 对引擎的意义

**缩进（G1）可以直接落**：`72pt + @left + @firstLine`，含悬挂。
引擎已有 `indent_left` / `indent_first_line`，本批确认了它的口径与 Word 一致。

**居中不要动**：G2 判假，而正确形式未知；照现在的「余量减半」写会差 0.117pt，
照实测凑一个常数进去则是拟合。
