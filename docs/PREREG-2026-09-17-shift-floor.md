## 0 为什么八个候选没穷尽该穷尽的

recursive 那一批把「闭式 / 递推 × 四种取整规则」8 个候选全判假了，
而且最优规则在两批之间换人（截断 168/244 → 256/304，取偶 182/244 → 240/304）。

但那八个没穷尽该穷尽的东西。**所有取整规则的差别，都等价于给被取整的量加一个常数**：

| 规则 | 等价写法 |
| --- | --- |
| 截断 | `⌊x⌋` |
| 四舍五入 | `⌊x + ½⌋` |
| 向上 | `⌊x + 1 − ε⌋` |
| 半数取偶 | `⌊x + ½⌋`，仅平局处微调 |

于是整族收成一个式子：

```
基线(n) 的格数 = ⌊A + n × step⌋        A 为待定实数
```

本批判的是**这个模型本身**，不是 A 的值。

## 1 顺带：有限精度（V17）**采集前就用算术排除了**

上一批的结论里把「Word 用 `double`，12.6 与 0.24 都不可精确表示」列为下一个方向。
**不必采了**：精确位置是 48 分之几格的有理数，它与整数的最小非零距离是
**1/48 ≈ 0.021 格**；`double` 在这个量级的误差约 **1e-13 格**，`float32` 也才 4e-5。
**比翻转一次判定所需的量小十个数量级。** 浮点误差不可能是原因。

## 2 容差

**0.0000pt**，逐位相等。位置一律用**有理数**算，全程不沾浮点。

## 3 预测

### U0 — 每条基线仍落在栅格上

分母 = **320**。第**十**次独立检验。

### U1 — 点预测：**存在**这样的 A

对每一组，令 `c(n)` 为第 n 条基线的格数（`n = 0 … 19`），`step = w:line × 10 / 48` 格。

```
存在实数 A，使得对全部 n： c(n) = ⌊A + n × step⌋
```

**怎么判**：每条基线把 A 限制在半开区间 `[c(n) − n×step, c(n)+1 − n×step)`。
取 20 个区间的交集，**非空即成立**。全程有理数，精确。

**这不是拟合。** 它不挑「最好的 A」，只问交集空不空——二值。
采集前已核鉴别力：真截断序列成立，**任意动一条**即不成立。

**判为假的读数**：任何一组的交集为空。分母 = **16**（16 组）。

- **成立** → 「位置 = 某个连续量截断」这个模型立住，剩下的问题只是 A 的形式；
- **判假** → **这个模型整个倒掉**，位置根本不是由一个连续量取整得来的。

## 4 另报（**不作预测**）

| | 判据 | 结果 | |
| --- | --- | ---: | --- |
| **U0** | 每条基线落在栅格上 | **320 / 320** | **成立** |
| **U1** | 存在实数 A 使 `c(n) = ⌊A + n × step⌋` | **16 / 16** | **成立** |

### U1 成立：模型立住了

这是累加机制上**第一个肯定性结论**。前面九批全是排除：更细的整数单位、
常数步长锚、量化次序、`usWinAscent`、起页方式、闭式四规则、递推四规则、
有限精度。现在知道了一件正面的事：

**位置确实是某个连续量的截断。** 剩下的问题只是那个量（A）长什么样。

A 不是同一个常数——a 组的区间 [0, 0.5) 与 c 组的 [0.5, 0.667) 根本不交。

### 探索性（§7.5 标「回测」，**不当独立检验**）

**A 依赖行距，不依赖字体。** 同一 `line` 下换字体，A 的区间与首行格数**逐格相同**：

| `w:line` | Brush Script MT | AppleMyungjo | 首行格数 |
| ---: | --- | --- | ---: |
| 228 | [0.0000, 0.5000) | [0.0000, 0.5000) | 338 / 338 |
| 232 | [0.3333, 0.6667) | [0.3333, 0.6667) | 339 / 339 |
| 236 | [0.5000, 0.6667) | [0.5000, 0.6667) | 339 / 339 |
| … | | | |

**8 / 8 完全一致。** 两个族的度量差得很远——Brush Script MT 的 ascent 是
1820/2048 em，AppleMyungjo 是 891/1025 em——`exact` 行距下却给出同一条基线，
**连首行都一样**。

与之相符：三个含 ascent 的候选形式，小数部分最多只中 8/16，
而且它们都是**常数**（同字体同字号），解释不了 A 随 `line` 变这件事。

**到此为止，不再往下凑。** 「`exact` 下基线与字体无关」是从已见数据看出来的，
要成为结论得有它自己的预注册和自己的夹具——而且该用度量**差得更极端**的族来判。

### 对引擎的意义

引擎仍不改。模型立住不等于知道 A，没有 A 就没有可落地的公式。
