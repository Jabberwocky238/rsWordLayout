## 0 一次判清单上三项

**H3d 两端对齐**、**H4 字距**都没碰过。三条预测各有各的绕开字体度量的办法，

**右边界 = 72 + 451.3 = 523.3pt**。

## 1 容差

**0.0000pt**，逐位相等。唯一例外：PDF 读数的十进制舍入取 **1e-6 pt**。

## 2 预测

### K0 — 每条基线仍落在栅格上

分母 = 采集到的全部基线。第**十六**次独立检验。

### K1 — 右对齐：行尾贴右边界

```
末字形的 x + 末字形的 advance = 523.3pt
```

两边都是**实测量**，右边界是**常数**——不必知道行宽，绕开了字体度量。

四段文本（2 / 8 / 16 / 24 字符）。**判为假的读数**：任何一段不等。分母 = **4**。

### K2 — 两端对齐：**非末行**拉满，末行不拉

两段长文本必然换行。

```
非末行：末字形的 x + advance = 523.3pt
末行　：**不**要求贴右边界
```

**判为假的读数**：任何一条非末行不贴右边界。分母 = 采集到的非末行条数。

> 末行**不判**——这是采集前就声明的范围：两端对齐不拉伸末行是 OOXML 的定义，
> 拿它当判据等于判一条规范条文，不是量 Word。

### K3 — 字距：`w:spacing` 逐字符加在推进量上

同一文本 `abcdefgh` 排四遍，`w:spacing` 分别是 0 / 20 / 40 / 80 半点
（0 / 1 / 2 / 4 pt）。记第 i 与第 i+1 个字形的 x 差为 `Δ(sp, i)`：

```
Δ(sp, i) − Δ(0, i) = sp / 2  pt        对每个 i
```

**字形本身的推进量在相减时消掉**，所以这条也不含字体度量。

**判为假的读数**：任何一个 `(sp, i)` 不等。分母 = 3 个非零字距 × 每段的字形间隔数。

## 3 采集前声明的排除项

- 右对齐组某段换了行 → 该段**判不了**。
- 两端对齐组若只排出一行（没换行）→ 该组**判不了**，因为没有「非末行」。
- 字距组四段的字形数若不相等 → **判不了**（无法逐位相减）。

## 5 采集条件

### K3 不成立，**是我把单位写错了**

预注册 §2 写「`w:spacing` 分别是 0 / 20 / 40 / 80 半点（0 / 1 / 2 / 4 pt）」。
**错了**：`w:spacing`（字符级）的单位是 **twips（1/20 磅）**，不是半点。
所以 `val=20` 是 **1pt**，不是 10pt。

实测每个间隔的差是 **1.0005pt**，与 twips 解释吻合到 0.0005pt。

**但判定照记为不成立。** 预注册写死的式子是 `sp/2`，实测不满足它，那就是不成立——
事后把单位改对再宣布通过，就是改判据迁就数据，那正是这套东西要挡的。
`w:spacing` 要有结论，得写一份**新的**预注册、采一份**新的**夹具。

（1.0005 而不是 1.0000 这 0.0005pt 的零头，也要那一批去查，本批不下结论。）

### K2 判不了，**是判据的 bug**

两段长文本报「没换行，1 行」。它们当然换行了——问题在判据：
按标签前缀 `startswith(tag)` 找行，只找得到段落的**第一行**，
第二行起的文本不以标签开头。此前每一批每段都只有一行，所以这个 bug 一直没露头。

**照记为判不了**（按 §3 的排除项：没有非末行可判）。修好判据要重采，
而重采得有新的预注册——同上，不事后补判。

### 探索性（§7.5 标「回测」，**不当独立检验**）

K1 的差与字符数正相关（0.036 → 0.050，字符数 2 → 24），量级是每字符约
**0.0007pt**。这像是**推进量求和的舍入**：右对齐要先算行宽，
而行宽是各字形推进量之和，每个都带一点舍入。

这与清单上的 **H2**（Δx 还剩 0.04pt 的尾巴）多半是同一件事——
两者的量级一致，都在 0.04 ~ 0.05pt。**到此为止，不再往下凑。**
