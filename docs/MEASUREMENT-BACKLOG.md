# 量具能测什么，已经测到哪儿

量具直接读到的只有四样（方法 §1 / §2）：**每个字形画在哪里**（`glyphOrigin`）、
**推进量**、**字形数**、**字体名**。页数与行划分来自行号扫描。
所有「规则」都只能从这四样推出来——推不出来的，就不在这份清单里。

每一行的「状态」只有三种：**已确立**、**已排除**、**未决**。
「看着像」不算状态。

实测它的失效是有形状的：汉字与它的**康熙部首**共用同一个字形，反查取了部首那个码位

## 2026-09-18 补记：证否条件 F1–F4 第一次被扫

上面 22 批的判定里，**方法的 F1–F4 一次都没进过判定**。23 个预注册脚本各自有一个
`falsifiers()`，扫的是 F-A（采前核查）/ F-B（字体替换）/ F-C（夹具身份）/ F-D（页集不符），
名字相同、内容不同。所以 `VERDICT.json` 里那 22 个 `"falsifiers": []`
是**「没扫」**，不是「扫过为零」（§7.4）。

补扫的结果：**F3 命中 442 行**，分布在五份采集包上——
shift-floor 160、recursive 160、page-start 61、font-free 40、noise-floor 21。
**全部是同一形**：AppleMyungjo 的子集字体把段落标记那个空格的 ToUnicode 写成 `\t`，
而身份核对的空白等价只认单向。不含该字体的 17 份一条都没有。

修掉等价规则后**五份全部归零，行分母一条不少**。所以
**V18 / V20 / H5 / V6 / V15 / V16 的判定不受影响**——那是子集表的伪影，不是配对失败。
但在 2026-09-18 之前，这句话没有人核过。详见
[`ENGINE-SWEEP-2026-09-18.md`](ENGINE-SWEEP-2026-09-18.md) M-2。

## 2026-09-22 补记：原生行号在两次紧邻扫描之间会变

用两份逐字节相同的夹具副本，在新起的本机 Word 16.112.3 里各做六次 252 个位置的观测。
`kinsoku` 六次全同。`kinsoku2` 的第一次扫描（与 PDF 导出同在一个 AppleScript 调用里）
给出跨四页 1..8 的行号，紧接着的第二次扫描在每一页上都只给 1 和 2——
**252 个行号里 189 个变了**。页号与源文行边界没变，两份新 PDF 的完整字形数组
与各自的旧采集在四页上**逐位相等**，且变化发生在任何显式重排版之前。
历史上那六次短前缀反转的机制仍未解释，这一例**也不证明**是后台重排版造成的。

所以新采集一律保留原有的「导出 → 首扫」序列，并**再紧接一次扫描**；
两次读数、哈希与 stdout 回执全部留档，首扫仍是 `sweep.json`。读数不一致、解析失败、
UTF-16 覆盖不全、代理对被切断或行号非法，一律把 `META.usability` 判成 UNDECIDABLE，
模型在配对之前就拒收，`wm capture` 退出码 2。
**没有重试到通过，也不拿第二次读数顶替第一次。** 两次一致也不等于行身份是对的。

这条只约束**往后**：没有任何一份旧采集因此被改判，也没有旧的 FAIL / VOID
被这些诊断读数扶正。`kinsoku` / `kinsoku2` 剩下的行数不符**仍然留着**——
在有独立的结构观测、或有讲得出道理的废采集闸门之前，不动引擎的断行。
